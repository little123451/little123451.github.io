## 2. 协作方式（这个用户吃这一套）

- **中文、直接、务实**，不要客套话与过度铺垫。
- **一次只聊一个话题**。用户是人，明确说过"你一下铺太开，我需要把话题聚焦"。
  → 给完一个话题的结论，再问下一个；同时展开多个方向会被要求收敛。
- **每轮只留一个决策点**（最多两个强相关的小确认），用"你选 A 还是 B"结尾。
- **先给事实与数字**（读代码 / 读数据核对），再给方案对比表（2–4 个）+ 推荐 + 代价。
- 用户喜欢**具体效果样例**：界面示意、真实文案、数值推演、玩家行为模拟，而不是抽象描述。
- 用户会**基于实际游玩反复调数值**；不要追求一次定死，方案要留"以后可调"的余地。
- 用户反对"为机制而机制"：新增系统必须**复用已有界面 / 资源 / 事件**。
- 用户很在意**设定自洽**：火箭队视角、把宝可梦当工具、研究的残酷感。
- 用户会自我怀疑（"是不是我自 high"），此时应**用数字或模拟给出诚实判断**，不要一味附和。

## 3. 跨话题的设计原则（讨论时默认遵守）

- **不考虑旧版本兼容**：存档、字段、旧逻辑都不做兼容层。
- **隐性设定**：UI 不明示公式 / 概率 / 阈值，只给结果与现象；写进 README 的隐性设定表。
- **信息展示**：与研究进度挂钩；但"没想好怎么解锁"的信息**默认可见，不设兜底**。
- **资格 vs 效率**：资格用物种级 meta（特性 / 分类），效率用个体级（等级 / 能力 / 特质）。
- **行为解锁优先**：蛋组 = 繁育确认；特性 / 分类 = 首次存活完成「组织采样」。
- **先小后大**：一次只扩一个系统；能先做垂直切片验证就不要铺全量。

## 6. 项目背景速查（避免重复踩坑）

- 时间：1 游戏日 = 12 真实秒；有 1x / 2x / 3x 倍速。
- 等级上限 60；研究需求 `40 + (255 − 捕获率) × 1.4`（烈雀 40，超梦 393）。
- 能力值公式同正作（无 EV 项）；IV 0–31、繁育取双亲均值 ±5；性格 25 种、±10%；**当前没有努力值**。
- 实验室：实验台 2–4；实验冷却 5–28 秒真实时间；物种 100% 后只剩一条实验；死亡留遗体、6 金处理。
