## 0. 讨论的范围与前提

- 起点问题：繁育会产生大量个体，但个体只有**出售 / 繁育 / 试验**三个出口，且三者都不消费"个体质量"，经营缺少策略。
- 讨论中确认的一条原则：**先把已有循环打磨好，再加新系统**；新用途必须复用已有界面 / 资源 / 事件，不新开一套系统。
- 本文按 A–E 五个方向记录讨论结论，再单独记录最大的"核心循环"问题。

## 1. 现状事实（讨论时核对过代码）

| 项目 | 现状 |
|---|---|
| 个体值 IV | 存在：0–31；繁育取双亲均值 ±5；市场蛋固定 10–20 |
| IV 的消费者 | **只有详情页展示**（`calcStats()` 仅被 ui 调用一次），没有任何玩法读取 |
| 努力值 EV | **不存在** |
| 性格 | 25 种，±10%，繁育 50/50 继承 |
| 能力值 | `calcStats()`，公式与正作一致（去掉 EV 项），按图鉴进度逐项披露 |
| 个体卡片显示 | 显示的是**个体实际能力值**；物种详情页才显示种族值。"看不出差距"是因为 Lv.60 下取整把 IV 差距压成 1–2 点 |
| 出售价格 | `物种基价 × (0.85 + 等级×0.015) × 0.45`，不看 IV/性格/能力值 |
| 部门订单 | 按属性 / 物种 / 性格 / 最低等级匹配，不看能力值 |
| 实验室 | 研究是物种级；损耗看实验档位的 atk/spa，不看个体能力 |
| 等级上限 | 60（`CONFIG.maxLevel`） |
| 特殊个体 | 只有闪光（视觉）与不孕/不育（负面），无其他特质 |

结论：**问题不是"个体值机制不存在"，而是"个体质量没有任何出口"**。

## 2. A · 让质量有买家

### 已认可的方向

- **部门偏好细化**：警卫队看攻击与等级、研究部看特攻与性格、通讯部看电系与速度、走私组看稀有度与综合评分——把"属性对口"升级为"能力对口"。**暂时纳入方向，不实施。**
- 订单**不设硬门槛**，改为质量溢价（同一单，个体越强报酬/声望越高），避免"差一点不能交"的挫败。
- 出售价格加入质量项（轻微即可）。

### 未定的设定缺口：卖给谁

玩家已经是火箭队成员，"出售"在叙事上没有对象。候选：

| 方案 | 说法 | 游戏性 |
|---|---|---|
| 上交组织 | 多余个体上交，换资金/配额 | 稳定低价，保底 |
| 黑市转手 | 通过走私组渠道出手 | 价格波动，看行情 |
| 部门截留 | 直接抵一部分部门需求 | 与订单系统合并，减少一个独立出口 |

倾向：**上交（保底）+ 黑市（波动）** 两条腿。**未拍板。**

### 备注

这条对"个体没意义"帮助有限——它仍是"把个体换成资源"，不产生"留存价值"。真正的留存价值要靠个体在某个系统里持续发挥作用（见 C）。

## 3. B · 持有成本

### 已认可

- **围栏容量上限，与图鉴解锁进度挂钩**：图鉴越全，组织越认可，给更多空间。方向认可，数值未定。

### 未定：成本形态

- 维护费（持续成本）**未想好**；且已有"争斗机制逼着卖个体"的负面体验，担心成本变成纯惩罚。

### 建议（待定）

- 用**阈值型压力**替代持续税费：未超容量零成本；超容量才付出（每日按超出数量扣，或强制处理）。平时不痛，超了才痛。
- 若要一点持续成本，优先复用已有资源：糖果被动经验分摊、超员声望流失、上交换配额。
- **不建议新增"饲料/金钱"这类纯消耗资源**（多一个资源就多一套平衡）。

### 与霸凌机制的关系

- 现在的霸凌（同种同性 ≥4 只，最弱被持续消耗）与容量机制功能重叠，且逼玩家卖个体，体验一般。
- 建议：合并为"超员时才触发"，让"该卖谁"由容量和需求决定。**未拍板。**

## 4. C · 增加用途

### 已有想法

- 驻守、拆解（早先想过，未细化）
- 借调、斗兽（本轮提出，符合设定）

### 担心

- 现有玩法未打磨好就加系统，后期管理与平衡成本过高。

### 准入规则（建议）

> 每个新用途必须复用一个已有的界面、资源或事件，不新开系统。

| 方向 | 复用什么 | 新增什么 | 风险 |
|---|---|---|---|
| 驻守 | 围栏下方 4 个空位（已在）、营救事件（设定已在） | 防御强度 = 个体能力 | 低 |
| 拆解 | 糖果、遗传 | 一个转化动作 | 低（易成最优解） |
| 借调 | 每日 tick、资金产出 | 每日结算 | 低 |
| 斗兽 | 订单判定框架、耐受度 | 胜负与奖金 | 中（与实验室死亡风险撞车） |

建议顺序：**驻守 → 拆解 → 借调 → 斗兽**。斗兽放最后。

## 5. D · 个体质量（本轮重点）

### 已决定

| # | 决定 | 内容 |
|---|---|---|
| D-1 | ✅ **质量可读** | 属于设计遗漏，玩家可以看到个体的能力水平，是可量化的 |
| D-2 | ✅ **能力值显示仍按图鉴进度逐步解锁** | 保持现有披露节奏不变 |
| D-3 | ✅ **等级上限保持 60** | 不上调至 100 |
| D-4 | ✅ **EV 采用正作数值** | 单项上限 252、六项合计 510 |
| D-5 | ✅ **新增"道具获取"入口** | 玩家发布道具需求订单 → 火箭队去掠夺（类似商店但换叙事） |
| D-6 | ✅ **EV 由道具提升** | 引入可增加努力值的道具 |
| D-7 | 🕒 **能力值的消费者** | **决定暂缓**：订单读能力值这条先不做，本轮先做"道具获取"系统；等订单改造时再接入 |

### 讨论中被修正的想当然

- ❌ "把等级上限提到 100 就能让 IV 压过 EV"：**不成立**。IV 与 EV 的贡献都乘同一个 `等级/100`，两者比例恒定（EV 252 折算 63 vs IV 31，约 **2.03 : 1**），与等级无关。
- 提高等级上限的真实好处是：Lv.100 时 1 点 IV = 1 点能力值，取整损耗消失，"质量可读"更干净；但代价是全系统重新标定（经验曲线、订单最低等级、耐受度上限、繁育节奏、单局时长）。
- 已放弃该方案，保持 60 级。

### Lv.60 下的"质量层级"（单项，种族值 100 为例）

| 层 | 0–最大值 | 谁决定 | 可改性 |
|---|---|---|---|
| EV 训练 | 0–37.8 | 玩家（道具） | 不可改（除洗点） |
| 性格 | ±约 18 | 出生 50/50 继承 | 不可改 |
| 个体值 | 0–18.6 | 出生/遗传 | 不可改 |
| 种族值 | 主体 | 物种 | 不变 |
| 等级 | 放大器 | 经验/糖果 | 可提升 |

关键推论：

- **EV 成为个体差异的主轴**（约占单项 37.8），个体从"遗传质量"转向"培养投入"。
- 510 总上限意味着单项满 252 只能满**两项**（504）——"走物攻+速度还是血+防"成为不可逆的押注，符合经营游戏的取舍感。
- **性格在 60 级的权重与 IV 相当**（±10% ≈ ±18 vs IV 满值 18.6），所以判断个体不能只看 IV。

### 必须点出的前提：能力值目前没有消费者

- `calcStats()` 只在详情页展示；订单、实验室、繁育都不读能力值。
- 即使加了 EV 道具，能力值变大也只是**详情页数字变大**，不改变任何玩法结果。
- 因此 D 的下一步不是"EV 怎么加"，而是**谁读能力值**。

### 建议的下一步（未拍板）

- **能力值的第一个消费者 = 部门订单**（复用现有订单系统，不新增玩法）：按能力定价/挑选，立刻让"练这只"有回报。
- EV 相关待定项：
  - 是否可重置（建议提供"清洗"道具，或允许直接重置）
  - 产出节奏（道具太多 EV 拉满失去意义，太少玩家卡住）
  - 是否显示训练标记（能力值照旧，但给每项一个小标记以示"投入过"，不显示具体 EV 值）

## 6. E · 稀有度与特殊个体

### 已认可

- 闪光、不孕不育目前只是"特殊个体"，后续计划加入**头目**等更多特殊个体，并赋予各自设定。
- 方向确认：**特殊个体在不同玩法里有不同价值**（例如头目上限下限都高；不孕不育主要在研究中有价值）。

### 建议框架（未拍板）

统一抽象为**特质（trait）+ 渠道价值**，新特质只填一行表，不新开系统：

| 特质 | 繁育 | 订单 | 研究 | 斗兽/驻守 |
|---|---|---|---|---|
| 闪光 | — | 溢价 | 进度加成 | 战力微量 |
| 不孕/不育 | 不能配 | — | 进度/低损耗（无繁殖负担） | — |
| 头目 | 遗传受限 | 高额溢价 | 高损耗（不耐折腾） | 高战力 |
| （未来） | … | … | … | … |

价值：

- 同一只个体在不同渠道价值不同 → "留着做什么"成为真实决策
- **特质是低成本的差异化手段**，比给 151 个物种各做独特机制便宜得多

## 7. 核心循环：151 次重复的问题

### 问题

- 设定上想引导玩家完成图鉴，但图鉴有 151 个；一条线再有趣，重复 151 次也会无聊。
- 本质不是"循环没设计好"，而是**把"内容量"当成了"目标"**。

### 三个可选方向

1. **把 151 从收束条件降级为长期成就**：单局收束由阶段性目标判定（如完成 30 个物种 + 达到某职级），151 变成跨局收集。单局长度可控，重复感被稀释。
2. **研究需求由订单拉动**：只有被部门点名的物种才值得研究，图鉴变成"发生过什么的记录"而不是待办清单。改动大，会削弱研究的主动性。
3. **物种分层**：旗舰（15–20 个，独特机制）/ 普通（流程化，靠特质与订单产生变化）/ 背景（只作为订单与市场出现）。玩家自己选择深度。

### 建议（未拍板）

**① + ③**：收束前置 + 物种分层。② 暂缓。

## 9. 推荐的推进顺序

1. 先定 **D**：能力值的消费者 + EV 的显示与重置（基础属性层）
2. 再定 **E**：特质框架（个体的差异化层）
3. 然后 **A/B**：出口与容量（建立在前两层之上）
4. 最后 **核心循环 / 收束**（最大、最容易返工，放最后）

理由：D 与 E 是"个体"这个对象的基础属性；A/B 都是建在它们之上的出口。基础没定，出口做出来还要返工。

## 10. 道具获取系统（讨论中，本轮主线）

> 因为能力值消费者暂缓（D-7），EV 道具目前只会改变详情页数字；
> 这批道具的阶段性意义是"成长资源"——给玩家可抢、可囤、可分配的东西。

### 10.1 已决定

| # | 决定 | 内容 |
|---|---|---|
| 10-1 | ✅ **独立 tab** | 与"部门需求"方向相反：部门向你要货，这里是你向组织要货 |
| 10-2 | ✅ **委托形态：混合** | 常规道具走"指定采购"（稳定、可规划）；稀有道具只能靠"目标掠夺"随机获得（有惊喜有风险） |
| 10-3 | ✅ **并入现有道具** | 进化石、通信电缆、经验糖果统一进这个入口；经营页的蛋贩子只保留卖蛋与换货 |

### 10.2 循环骨架

```
发布需求 → 火箭队出发 → 等若干天 → 带回战利品（或空手）→ 入库
```

### 10.3 目标设计（建议，未拍板）

可复用已有的 **300 条来源地点**文案（黑市中间人、走私船货舱、海关扣押仓库、火箭队运输车…）作为掠夺目标，按档位分组：

| 档位 | 示例 | 耗时 | 成本 | 成功率 | 产出 |
|---|---|---|---|---|---|
| 安全 | 近郊杂货铺 | 2 天 | 低 | 90% | 常规 EV 道具 |
| 普通 | 黑市仓库 | 3 天 | 中 | 75% | 常规 + 小概率稀有 |
| 冒险 | 海关扣押仓库 | 5 天 | 高 | 60% | 稀有概率较高 |
| 危险 | 火箭队运输车 | 7 天 | 免费 | 45% | 稀有概率最高，失败损失大 |

### 10.4 EV 道具粒度（建议，未拍板）

- 每颗 **+30 EV**（上限仍单项 252 / 总 510）
- 满一项约 9 颗；喂满一只约 17 颗
- 若每次委托带回 1–3 颗，喂满一只约 **6–10 次委托**

### 10.5 风险与反通胀（共识方向）

- 失败只损失时间与部分预付资金，**不损失个体**（个体死亡继续集中在实验室）
- 成功率与目标价值反相关，可随职级小幅提升
- 并发委托数随职级增长；目标列表定期刷新
- **不新增资源**（不做配额 / 行动力），用资金 + 时间 + 风险做取舍

### 10.6 待定

- [ ] 指定采购与掠夺是否**共享并发槽位**（若共享，"稳定 vs 惊喜"的取舍才成立）
- [ ] 可指定的道具范围（只限常规 EV 道具？洗点道具是否可指定）
- [ ] 每档的具体产出表与概率
- [ ] 洗点道具（重置 EV）的来源与稀有度
- [ ] tab 名称：采购 / 物资 / 掠夺委托（倾向"物资"，动词化可叫"要货"）

### 10.7 定位补充：这是"道具容器"，不是 EV 专线

讨论确认：**EV 道具只是第一批道具**，后续会按游戏设定与正作道具的匹配度逐步增加。
因此这套系统要按"道具目录 + 获取渠道"来设计，而不是围绕 EV 写死。

建议的道具元数据（每条道具都要能填）：

| 字段 | 说明 |
|---|---|
| 分类 | 培育 / 研究 / 经营 / 特质 / 消耗品 |
| 获取渠道 | 可指定采购 / 只能掠夺 / 剧情或活动限定 |
| 稀有度 | 普通 / 稀有 / 极稀有（决定出现在哪一档目标里） |
| 价格 | 指定采购的固定价；掠夺线不标价，由目标成本体现 |
| 效果 | 作用对象（个体 / 蛋 / 栏位 / 全局）与数值 |
| 是否消耗 | 大部分消耗；少部分可重复使用 |

取舍原则（未拍板）：

- 本作**没有对战**，正作里偏战斗的道具（携带道具、树果、PP 提升等）价值低；
  优先挑"经营 / 培育 / 研究"类。
- 新增道具必须能挂到**现有玩法**上，否则只是又一个数字。
- 现有经营页的进化石与通信电缆、经验糖果 **已决定并入这个新入口**（见 10-3）；
  蛋贩子只保留卖蛋与换货，不再卖道具。

### 10.8 并入后的结构（建议，待拍板）

并入之后，"新 tab"里其实有两条不同的购买方式，需要先定节奏：

| 方式 | 确定性 | 耗时 | 占槽 | 定位 |
|---|---|---|---|---|
| **指定采购** | 必得 | 即时到货 | 不占 | 花钱买确定性，但**限量**（每类每日 1–2 件） |
| **目标掠夺** | 随机 | 2–7 天 | 占 | 花时间赌收益，可能出稀有 |

这样"混合"的取舍落在**钱 / 时间 / 确定性**三者的交换上，且保留了现有"点一下就到账"的商店手感；
稀缺性由"限量刷新"提供，而不是给每颗糖果都加等待时间。

如果改成"采购也要等 1–2 天"，体验会更像下军令，但日常消耗品（糖果）会变得繁琐。

### 10.9 新方向：个体作为"任务工具"（讨论中）

> 讨论中提出的方向：**派玩家培育的个体去执行掠夺任务，用个体的类型 / 特性 / 性格 / 能力等 meta 决定它能不能去、去得多好。**
> 目标：让"定向培育符合某种功能的宝可梦"成为经营策略，同时利用物种多样性，并贴合"火箭队把宝可梦当工具"的设定。

#### 为什么这个方向比"出售"有策略

- 出售是"把个体换成资源"，个体本身没有留存价值；任务派工是"个体持续产出"，且**派谁**会改变结果。
- 当任务需求由外部（目标场景）决定时，个体从"可互换的数量"变成"有岗位适配性的人员"。
- 繁育的目标从"多生"变成"生出能干某件事的个体"，闭环变成：
  **看任务需求 → 定向培育 → 派工 → 得道具 → 道具强化个体 → 接更难的活**

#### 设计原则（避免变成无聊玩法）

1. **资格与效率分离**：门槛决定"能不能去"（制造培育目标），效率决定"去得多好"（制造选优空间）。
2. **占用即代价**：任务期间个体不可用于繁育 / 出售 / 实验，形成机会成本。
3. **惩罚要轻**：失败主要是空手、掉耐受、轻伤；不轻易致死（死亡继续集中在实验室）。
4. **不新增系统**：任务只读已有 meta，不引入新资源。
5. **首版极简**：单任务、1–2 个需求标签、不做团队多槽、不做熟练度。

#### 资格维度（已决定）

- ❌ **不用性格**：25 种、池子大、目前没有变更手段，难以定向培育，容易把玩家卡住。
- ✅ **用特性 + 宝可梦分类（种类）**：这两类是与数值基本无关的 meta，适合作为机制门槛，也贴合"火箭队把宝可梦当工具"的设定。
- 注意：分类（genus，如"种子宝可梦"）此前因"没有用处"被整体删除（`fetch-data` 与 `dex.json` 都已剔除），现在要恢复。

#### 数据现状（2026-11-19 核对）

| meta | 分布 | 可观测 | 可定向 |
|---|---|---|---|
| 特性 | 151 物种：1 个的 6 种、2 个的 46 种、3 个的 99 种（含隐藏特性） | ❌ 不显示 | ❌ 随机、不遗传 |
| 分类 | 每物种 1 个（如"种子宝可梦""鸟类宝可梦"） | ❌ 已删除 | ✅ 选物种即定向 |

**结论**：分类天然可定向（选物种）；特性若保持"从 2–3 个里随机"，就会重演性格的问题。
因此在把特性当门槛之前，必须先定它的定向方式（见待定）。

#### 资格 vs 效率（两层）

- **资格（能不能去）**：物种级 meta（特性、分类）——制造"该繁育哪些物种"的目标。
- **效率（去得多好）**：个体级（等级、能力值、特质）——制造"派哪一只更强"的选择。
- 两层分开，既利用物种多样性，又不丢掉个体质量的意义。

#### 一个顺手的价值点：不孕不育

不孕/不育目前是纯负面。若任务系统存在，它们天然适合**高危任务**（没有繁殖价值，派出去不怕损失），
可以把"负面特质"变成"岗位适配"。同理，头目适合硬碰硬的任务，闪光适合需要稀有度的任务。

#### 待定

- [ ] **特性的定向方式**：A. 每物种固定主特性（`abilities[0]`，确定但特性门槛≈物种门槛）／B. 特性可遗传（多一层培育深度，但要先解决显示）／C. 特性胶囊道具（由掠夺产出）
- [ ] 分类字段的恢复方式（重新抓取 / 在 `data.mjs` 加覆盖表）
- [ ] 特性的可观测方式（直接显示 / 随研究进度披露）
- [ ] 任务失败的具体代价（掉多少耐受、是否受伤、是否可能逃跑/死亡）
- [ ] 是否允许多个个体同时执行一个任务（团队制会显著增加复杂度）
- [ ] 任务需求是明确显示还是模糊描述（模糊 → 更贴"研究"，但可能让玩家试错成本过高）

### 10.10 信息披露原则：所有个体信息都跟"研究进度"走

> 讨论确认的大方向：**个体的信息展示与披露，统一挂在物种研究进度上**，以强化"研究"这一行为的存在感。
> 特性此前因为没用被隐藏，现在既然要作为门槛，就恢复显示——但显示时机同样受研究进度控制。

#### 现状的不一致点

- 个体卡片：属性徽章、性格、等级一直显示
- 物种详情：属性、种族值按研究进度隐藏（未研究显示 `？？？`）
- 特性：完全不显示
- 分类：已删除
- 蛋组：另一套规则（繁育确认 / 研究 100% 补全）

同一份信息在"个体"和"物种"两个界面里的可见性不一致，玩家会困惑。

#### 建议：能力值按"解锁序列"逐项披露（草案）

这是**唯一需要测量**的信息，所以它继续按研究进度逐项公开：

```
六项能力值（按种族值从高到低）
```

- 研究进度条 = 测量进度，每约 16.7% 公开一项，100% 全部公开（与现有实现一致）
- 卡片上的 `？？？` 会随着研究推进逐项消失，玩家能感觉到"我越来越认识它了"
- 特性、分类、性格等**不上这条序列**，默认可见（见下）

#### 特性 / 分类：由「组织采样」解锁（已决定）

讨论最终确定：**特性与分类不做"默认可见"，改为行为解锁**。

| 项目 | 规则 |
|---|---|
| **解锁动作** | 对该物种的任意个体**首次完成「组织采样」且该个体存活** |
| **成功率** | 采样过程中个体死亡 **不算解锁**（已决定）；需要换一只再做 |
| **解锁范围** | **物种级**：一次解锁，该物种所有个体都可见分类与其自身特性 |
| **解锁内容** | 分类（种类）+ 特性（个体各自的特性随之可见） |
| **解锁前表现** | 卡片显示"特性未知 / 分类未知" |
| **派工拦截** | **只拦任务点名要求的标签**（已决定）：任务要求特性/分类、而该个体信息未知 → 不能派；任务没要求 → 不拦 |

理由与设定：你是研究员，取样之后才知道它是什么种类、有什么特性；
这也让「组织采样」这个基础实验有了研究之外的实际用途。

#### ⚠ 已知实现问题：有 6 个物种做不了「组织采样」

核对数据（2026-11-19）：专属实验条数分布 `{2:2, 3:143, 4:5, 5:1}`。
`experimentsFor()` 的补入规则是"不足 5 条才从基础三条里补"，具体补入顺序是 `对战 → 采样 → 体测`：

| 专属条数 | 补入内容 | 能否做组织采样 |
|---|---|---|
| 2 | 对战 + 采样 + 体测 | ✅ |
| 3 | 对战 + 采样 | ✅ |
| 4 | 只有对战 | ❌ |
| 5（#003 妙蛙花） | 不补 | ❌ |

也就是说：**5 个 4 条专属的物种 + 妙蛙花，永远无法通过采样解锁特性/分类**。

**已决定采用方案 A：让「组织采样」常驻**——不受补入规则影响，所有物种的实验室里都能看到它。
实施时的副作用：这 6 个物种的实验列表变成 5–6 条，
而"未做过的实验各压 2% 进度上限"的公式（`unperformed × 2%`）需要重新校准。

#### 由此产生的冲突：任务资格依赖"已知信息"

掠夺任务若按特性 / 分类筛人，玩家必须先"认识"这只个体。三种处理（未拍板）：

| 处理 | 效果 |
|---|---|
| **盲派** | 信息未知也能派，靠结果反推（贴"研究"，但试错成本高） |
| **禁止** | 信息未知的个体不能派 → 逼玩家先研究该物种（门槛清晰，但可能卡住） |
| **模糊提示** | 显示"看着像是能派上用场的"之类定性判断，不保证 |

#### 待定

- [x] 任务资格在信息未知时的处理：**拦截**（已决定，见上表）
- [x] 采样过程中个体死亡：**不算解锁**
- [x] 拦截范围：**只拦任务点名要求的标签**
- [ ] ~~**采样可用性**：方案 A（常驻）／方案 B（独立动作）~~ → **已定：方案 A**，注意重算 `unperformed × 2%`
- [ ] 任务界面如何提示"需要先做组织采样"
- [ ] 个体卡片与物种详情的可见性是否要统一到同一套规则

### 10.11 美术：性别立绘（讨论中）

**现状**：`data/sprites/` 里每个物种只有一张 `{id}.png`（默认图），`sprite(id)` 不带性别；
性别只靠卡片上的 `♂ / ♀ / —` 符号区分。抓取脚本也只抓默认图，没有 female 目录。

**事实**：PokeAPI 的 `sprites/pokemon/female/{id}.png` 提供雌性立绘，但**第一世代里有性别差异的物种很少**
（典型如皮卡丘的尾巴缺口），其余多为第四世代之后才追加的差异。

**讨论结论（未拍板）**：

- 卡片上的立绘只有约 64px，细微差异（尾巴缺口之类）很可能看不清；性别符号仍然是更可靠的识别方式。
- 若要做，正确做法是**只补确有差异的少数物种**，并让 `sprite(id, gender)` 在缺失时回退默认图，
  不要为了统一给 151 个物种都放大一套 female 图。
- 视觉差异属于"一眼看到"的观察，**不应受研究进度限制**（与研究解锁的是"知识"，不是"外观"）。

- [ ] 是否加入性别立绘；若加，先确认第一世代实际有差异的物种清单
- [ ] 是否需要"熟练度/专精"（建议首版不做）

## 11. 实验室与研究（讨论中）

### 11.1 现状数字与痛点

- 研究需求 = `40 + (255 − 捕获率) × 1.4`：烈雀 40、皮卡丘 131、化石翼龙 334、超梦 393
- 一轮实验（5–8 条各做一次）约给 30–40 点进度 → 稀有物种约需 10 轮、**60–80 次点击**
- harsh 档一次损耗约 110 点耐受 → Lv.1 个体一击即死
- 物种研究 100% 后：只剩最伤身那条实验，不再记日志，实验室对该物种基本失去意义

三个结构性问题：

1. **决策不可见**：成本只标资金，耐受损耗与进度收益都隐藏，玩家只能凭经验记，谈不上权衡
2. **产出单一且一次性**：只产出"研究进度"，100% 后变成真空
3. **物种同质**：458 条专属实验只是文案不同，机制都是三档，151 次体验高度重复

### 11.2 新方向：满研究后转为"献祭式产出"

讨论确定的方向（**先只做产出端，消费端以后再说**）：

| 项目 | 决定 |
|---|---|
| **动作名称** | **「终末榨取」**（四个字；文案里不再出现"实验"） |
| **可用动作** | 研究 100% 后，只保留 **1 条终末榨取**（原计划 5 条极端实验，为避免铺开缩减） |
| **样本结局** | 这条动作**一次就耗死样本**（必死，不留活口） |
| **产物数量** | 由样本的**当前耐受度**决定，再叠加随机影响（正态分布） |
| **产物种类** | 先只做 **1 种产物**（不做 5 种） |
| **消费端** | 暂不设计（后续再定：加速研究 / 研究部订单 / 其他） |

### 11.3 产物公式草案（正态分布）

讨论确定：**产物数量用正态分布**——大多数情况落在平均数附近，少数情况会明显偏多（或偏少）。

参数建议：

```
μ = max(1, 当前耐受 / 35)       // 平均产出，随耐受提升
σ = max(0.6, μ × 0.3)           // 波动幅度
数量 = clamp(round(正态(μ, σ)), 1, 上限)
```

概率表现（σ = 0.3μ）：

| 样本耐受 | μ | 常见区间（±1σ） | 偶尔偏多（≥μ+2σ，约 2.3%） | 极罕见（≥μ+3σ，约 0.1%） |
|---|---|---|---|---|
| 100 | 2.9 | 2–4 | 4–5 | 5–6 |
| 158 | 4.5 | 3–6 | 7–8 | 8–9 |
| 273 | 7.8 | 6–10 | 11–12 | 13+ |

实现说明：游戏用的是种子化 LCG，取两次 `random()` 做 Box–Muller（或四次均匀数叠加近似正态）即可，
仍然是可复现的确定性随机。

设计要点：

- 用**当前剩余耐受**而不是上限：先拿去繁育/实验过的个体，献祭时产物更少 → "留着献祭还是先用"成为取舍
- **正态的尾巴是对称的**：偶尔也会明显偏少。**已决定：暂不保底**，先按完整正态跑，后续按游玩体验再调整
- 上限要设，否则极端值会失控（建议 ≤ 2μ，待定）

### 11.4 命名、文案与呈现（已决定）

| 项目 | 决定 |

### 11.6 实验流程改造（已决定）

| 项目 | 决定 | 理由 |
|---|---|---|
| **实验条数** | **保留 5–8 条** | 重复执行已经秒结算，多点几下成本低；458 条专属实验的内容不浪费 |
| **实验冷却** | **保留**（5–28 秒真实时间，按个体+实验） | 它防的是"连续点同一格"，也是现在唯一的节奏来源 |
| **递减收益** | **不做** | 实验室的选择被定义为**效率题**：harsh 永远最优，这是设计而不是缺陷 |
| **"各做一次才能到 100%"** | 保留（现有 `未做数 × 2%` 上限） | 唯一还保证其他实验被看到一次的东西 |
| **重复执行的加载条** | 删除（只在首次保留） | 减少每次点击的摩擦 |
| **重复执行的结果卡** | 删除，只写一条日志 | 玩家第三轮之后不会读；文案留在日志里可回看 |
| **实验日志逻辑** | **不改**：每次实验（含重复）照常写入研究笔记的实验日志 | 实验体很少能熬过 10 次实验；玩家倾向最高档时，1–2 次就会把一只用死，日志量不会失控 |
| **首次执行** | 保留加载条 + 完整结果卡 | 仪式感与物种风味集中在这里 |
| **死亡 / 研究完成** | 总是弹卡 + 日志高亮 | 重要事件必须被看见 |

#### 为什么保留冷却（讨论记录）

原本冷却的作用是"防止玩家只做压力最大的实验"。但按现值算，**资源效率最高的其实是 gentle**，
harsh 的优势只是"每次点击给得多"；而个体过剩时，玩家不在乎消耗，所以效率最优就是 harsh。
这个"玩家总选最高档"的现象无法用递减收益纠正（递减只会让玩家改成两个按钮轮流点），
因此决定：**接受效率题的本质，把冷却保留下来作为节奏控制，其余摩擦全部去掉**。
