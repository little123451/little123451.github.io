## 0. 讨论的范围与前提

- 起点问题：繁育会产生大量个体，但个体只有**出售 / 繁育 / 试验**三个出口，且三者都不消费"个体质量"，经营缺少策略。
- 讨论中确认的一条原则：**先把已有循环打磨好，再加新系统**；新用途必须复用已有界面 / 资源 / 事件，不新开一套系统。
- 本文按 A–E 五个方向记录讨论结论，再单独记录最大的"核心循环"问题。

## 1. 现状事实（讨论时核对过代码）

| 项目 | 现状 |
|---|---|
| 个体值 IV | 存在：0–31；繁育取双亲均值 ±5；市场蛋固定 10–20 |
| IV 的消费者 | **只有详情页展示**（`calcStats()` 仅被 ui 调用一次），没有任何玩法读取 |
| 努力值 EV | **不存在** |
| 性格 | 25 种，±10%，繁育 50/50 继承 |
| 能力值 | `calcStats()`，公式与正作一致（去掉 EV 项），按图鉴进度逐项披露 |
| 个体卡片显示 | 显示的是**个体实际能力值**；物种详情页才显示种族值。"看不出差距"是因为 Lv.60 下取整把 IV 差距压成 1–2 点 |
| 出售价格 | `物种基价 × (0.85 + 等级×0.015) × 0.45`，不看 IV/性格/能力值 |
| 部门订单 | 按属性 / 物种 / 性格 / 最低等级匹配，不看能力值 |
| 实验室 | 研究是物种级；损耗看实验档位的 atk/spa，不看个体能力 |
| 等级上限 | 60（`CONFIG.maxLevel`） |
| 特殊个体 | 只有闪光（视觉）与不孕/不育（负面），无其他特质 |

结论：**问题不是"个体值机制不存在"，而是"个体质量没有任何出口"**。

## 2. A · 让质量有买家

### 已认可的方向

- **部门偏好细化**：警卫队看攻击与等级、研究部看特攻与性格、通讯部看电系与速度、走私组看稀有度与综合评分——把"属性对口"升级为"能力对口"。**暂时纳入方向，不实施。**
- 订单**不设硬门槛**，改为质量溢价（同一单，个体越强报酬/声望越高），避免"差一点不能交"的挫败。
- 出售价格加入质量项（轻微即可）。

### 未定的设定缺口：卖给谁

玩家已经是火箭队成员，"出售"在叙事上没有对象。候选：

| 方案 | 说法 | 游戏性 |
|---|---|---|
| 上交组织 | 多余个体上交，换资金/配额 | 稳定低价，保底 |
| 黑市转手 | 通过走私组渠道出手 | 价格波动，看行情 |
| 部门截留 | 直接抵一部分部门需求 | 与订单系统合并，减少一个独立出口 |

倾向：**上交（保底）+ 黑市（波动）** 两条腿。**未拍板。**

### 备注

这条对"个体没意义"帮助有限——它仍是"把个体换成资源"，不产生"留存价值"。真正的留存价值要靠个体在某个系统里持续发挥作用（见 C）。

## 3. B · 持有成本

### 已认可

- **围栏容量上限，与图鉴解锁进度挂钩**：图鉴越全，组织越认可，给更多空间。方向认可，数值未定。

### 未定：成本形态

- 维护费（持续成本）**未想好**；且已有"争斗机制逼着卖个体"的负面体验，担心成本变成纯惩罚。

### 建议（待定）

- 用**阈值型压力**替代持续税费：未超容量零成本；超容量才付出（每日按超出数量扣，或强制处理）。平时不痛，超了才痛。
- 若要一点持续成本，优先复用已有资源：糖果被动经验分摊、超员声望流失、上交换配额。
- **不建议新增"饲料/金钱"这类纯消耗资源**（多一个资源就多一套平衡）。

### 与霸凌机制的关系

- 现在的霸凌（同种同性 ≥4 只，最弱被持续消耗）与容量机制功能重叠，且逼玩家卖个体，体验一般。
- 建议：合并为"超员时才触发"，让"该卖谁"由容量和需求决定。**未拍板。**

## 4. C · 增加用途

### 已有想法

- 驻守、拆解（早先想过，未细化）
- 借调、斗兽（本轮提出，符合设定）

### 担心

- 现有玩法未打磨好就加系统，后期管理与平衡成本过高。

### 准入规则（建议）

> 每个新用途必须复用一个已有的界面、资源或事件，不新开系统。

| 方向 | 复用什么 | 新增什么 | 风险 |
|---|---|---|---|
| 驻守 | 围栏下方 4 个空位（已在）、营救事件（设定已在） | 防御强度 = 个体能力 | 低 |
| 拆解 | 糖果、遗传 | 一个转化动作 | 低（易成最优解） |
| 借调 | 每日 tick、资金产出 | 每日结算 | 低 |
| 斗兽 | 订单判定框架、耐受度 | 胜负与奖金 | 中（与实验室死亡风险撞车） |

建议顺序：**驻守 → 拆解 → 借调 → 斗兽**。斗兽放最后。

## 5. D · 个体质量（本轮重点）

### 已决定

| # | 决定 | 内容 |
|---|---|---|
| D-1 | ✅ **质量可读** | 属于设计遗漏，玩家可以看到个体的能力水平，是可量化的 |
| D-2 | ✅ **能力值显示仍按图鉴进度逐步解锁** | 保持现有披露节奏不变 |
| D-3 | ✅ **等级上限保持 60** | 不上调至 100 |
| D-4 | ✅ **EV 采用正作数值** | 单项上限 252、六项合计 510 |
| D-5 | ✅ **新增"道具获取"入口** | 玩家发布道具需求订单 → 火箭队去掠夺（类似商店但换叙事） |
| D-6 | ✅ **EV 由道具提升** | 引入可增加努力值的道具 |
| D-7 | 🕒 **能力值的消费者** | **决定暂缓**：订单读能力值这条先不做，本轮先做"道具获取"系统；等订单改造时再接入 |

### 讨论中被修正的想当然

- ❌ "把等级上限提到 100 就能让 IV 压过 EV"：**不成立**。IV 与 EV 的贡献都乘同一个 `等级/100`，两者比例恒定（EV 252 折算 63 vs IV 31，约 **2.03 : 1**），与等级无关。
- 提高等级上限的真实好处是：Lv.100 时 1 点 IV = 1 点能力值，取整损耗消失，"质量可读"更干净；但代价是全系统重新标定（经验曲线、订单最低等级、耐受度上限、繁育节奏、单局时长）。
- 已放弃该方案，保持 60 级。

### Lv.60 下的"质量层级"（单项，种族值 100 为例）

| 层 | 0–最大值 | 谁决定 | 可改性 |
|---|---|---|---|
| EV 训练 | 0–37.8 | 玩家（道具） | 不可改（除洗点） |
| 性格 | ±约 18 | 出生 50/50 继承 | 不可改 |
| 个体值 | 0–18.6 | 出生/遗传 | 不可改 |
| 种族值 | 主体 | 物种 | 不变 |
| 等级 | 放大器 | 经验/糖果 | 可提升 |

关键推论：

- **EV 成为个体差异的主轴**（约占单项 37.8），个体从"遗传质量"转向"培养投入"。
- 510 总上限意味着单项满 252 只能满**两项**（504）——"走物攻+速度还是血+防"成为不可逆的押注，符合经营游戏的取舍感。
- **性格在 60 级的权重与 IV 相当**（±10% ≈ ±18 vs IV 满值 18.6），所以判断个体不能只看 IV。

### 必须点出的前提：能力值目前没有消费者

- `calcStats()` 只在详情页展示；订单、实验室、繁育都不读能力值。
- 即使加了 EV 道具，能力值变大也只是**详情页数字变大**，不改变任何玩法结果。
- 因此 D 的下一步不是"EV 怎么加"，而是**谁读能力值**。

### 建议的下一步（未拍板）

- **能力值的第一个消费者 = 部门订单**（复用现有订单系统，不新增玩法）：按能力定价/挑选，立刻让"练这只"有回报。
- EV 相关待定项：
  - 是否可重置（建议提供"清洗"道具，或允许直接重置）
  - 产出节奏（道具太多 EV 拉满失去意义，太少玩家卡住）
  - 是否显示训练标记（能力值照旧，但给每项一个小标记以示"投入过"，不显示具体 EV 值）

## 6. E · 稀有度与特殊个体

### 已认可

- 闪光、不孕不育目前只是"特殊个体"，后续计划加入**头目**等更多特殊个体，并赋予各自设定。
- 方向确认：**特殊个体在不同玩法里有不同价值**（例如头目上限下限都高；不孕不育主要在研究中有价值）。

### 建议框架（未拍板）

统一抽象为**特质（trait）+ 渠道价值**，新特质只填一行表，不新开系统：

| 特质 | 繁育 | 订单 | 研究 | 斗兽/驻守 |
|---|---|---|---|---|
| 闪光 | — | 溢价 | 进度加成 | 战力微量 |
| 不孕/不育 | 不能配 | — | 进度/低损耗（无繁殖负担） | — |
| 头目 | 遗传受限 | 高额溢价 | 高损耗（不耐折腾） | 高战力 |
| （未来） | … | … | … | … |

价值：

- 同一只个体在不同渠道价值不同 → "留着做什么"成为真实决策
- **特质是低成本的差异化手段**，比给 151 个物种各做独特机制便宜得多

## 7. 核心循环：151 次重复的问题

### 问题

- 设定上想引导玩家完成图鉴，但图鉴有 151 个；一条线再有趣，重复 151 次也会无聊。
- 本质不是"循环没设计好"，而是**把"内容量"当成了"目标"**。

### 三个可选方向

1. **把 151 从收束条件降级为长期成就**：单局收束由阶段性目标判定（如完成 30 个物种 + 达到某职级），151 变成跨局收集。单局长度可控，重复感被稀释。
2. **研究需求由订单拉动**：只有被部门点名的物种才值得研究，图鉴变成"发生过什么的记录"而不是待办清单。改动大，会削弱研究的主动性。
3. **物种分层**：旗舰（15–20 个，独特机制）/ 普通（流程化，靠特质与订单产生变化）/ 背景（只作为订单与市场出现）。玩家自己选择深度。

### 建议（未拍板）

**① + ③**：收束前置 + 物种分层。② 暂缓。

## 9. 推荐的推进顺序

1. 先定 **D**：能力值的消费者 + EV 的显示与重置（基础属性层）
2. 再定 **E**：特质框架（个体的差异化层）
3. 然后 **A/B**：出口与容量（建立在前两层之上）
4. 最后 **核心循环 / 收束**（最大、最容易返工，放最后）

理由：D 与 E 是"个体"这个对象的基础属性；A/B 都是建在它们之上的出口。基础没定，出口做出来还要返工。

## 10. 道具获取系统（讨论中，本轮主线）

> 因为能力值消费者暂缓（D-7），EV 道具目前只会改变详情页数字；
> 这批道具的阶段性意义是"成长资源"——给玩家可抢、可囤、可分配的东西。

### 10.1 已决定

| # | 决定 | 内容 |
|---|---|---|
| 10-1 | ✅ **独立 tab** | 与"部门需求"方向相反：部门向你要货，这里是你向组织要货 |
| 10-2 | ✅ **委托形态：混合** | 常规道具走"指定采购"（稳定、可规划）；稀有道具只能靠"目标掠夺"随机获得（有惊喜有风险） |
| 10-3 | ✅ **并入现有道具** | 进化石、通信电缆、经验糖果统一进这个入口；经营页的蛋贩子只保留卖蛋与换货 |

### 10.2 循环骨架

```
发布需求 → 火箭队出发 → 等若干天 → 带回战利品（或空手）→ 入库
```

### 10.3 目标设计（建议，未拍板）

可复用已有的 **300 条来源地点**文案（黑市中间人、走私船货舱、海关扣押仓库、火箭队运输车…）作为掠夺目标，按档位分组：

| 档位 | 示例 | 耗时 | 成本 | 成功率 | 产出 |
|---|---|---|---|---|---|
| 安全 | 近郊杂货铺 | 2 天 | 低 | 90% | 常规 EV 道具 |
| 普通 | 黑市仓库 | 3 天 | 中 | 75% | 常规 + 小概率稀有 |
| 冒险 | 海关扣押仓库 | 5 天 | 高 | 60% | 稀有概率较高 |
| 危险 | 火箭队运输车 | 7 天 | 免费 | 45% | 稀有概率最高，失败损失大 |

### 10.4 EV 道具粒度（建议，未拍板）

- 每颗 **+30 EV**（上限仍单项 252 / 总 510）
- 满一项约 9 颗；喂满一只约 17 颗
- 若每次委托带回 1–3 颗，喂满一只约 **6–10 次委托**

### 10.5 风险与反通胀（共识方向）

- 失败只损失时间与部分预付资金，**不损失个体**（个体死亡继续集中在实验室）
- 成功率与目标价值反相关，可随职级小幅提升
- 并发委托数随职级增长；目标列表定期刷新
- **不新增资源**（不做配额 / 行动力），用资金 + 时间 + 风险做取舍

### 10.6 待定

- [ ] 指定采购与掠夺是否**共享并发槽位**（若共享，"稳定 vs 惊喜"的取舍才成立）
- [ ] 可指定的道具范围（只限常规 EV 道具？洗点道具是否可指定）
- [ ] 每档的具体产出表与概率
- [ ] 洗点道具（重置 EV）的来源与稀有度
- [ ] tab 名称：采购 / 物资 / 掠夺委托（倾向"物资"，动词化可叫"要货"）

### 10.7 定位补充：这是"道具容器"，不是 EV 专线

讨论确认：**EV 道具只是第一批道具**，后续会按游戏设定与正作道具的匹配度逐步增加。
因此这套系统要按"道具目录 + 获取渠道"来设计，而不是围绕 EV 写死。

建议的道具元数据（每条道具都要能填）：

| 字段 | 说明 |
|---|---|
| 分类 | 培育 / 研究 / 经营 / 特质 / 消耗品 |
| 获取渠道 | 可指定采购 / 只能掠夺 / 剧情或活动限定 |
| 稀有度 | 普通 / 稀有 / 极稀有（决定出现在哪一档目标里） |
| 价格 | 指定采购的固定价；掠夺线不标价，由目标成本体现 |
| 效果 | 作用对象（个体 / 蛋 / 栏位 / 全局）与数值 |
| 是否消耗 | 大部分消耗；少部分可重复使用 |

取舍原则（未拍板）：

- 本作**没有对战**，正作里偏战斗的道具（携带道具、树果、PP 提升等）价值低；
  优先挑"经营 / 培育 / 研究"类。
- 新增道具必须能挂到**现有玩法**上，否则只是又一个数字。
- 现有经营页的进化石与通信电缆、经验糖果 **已决定并入这个新入口**（见 10-3）；
  蛋贩子只保留卖蛋与换货，不再卖道具。

### 10.8 并入后的结构（建议，待拍板）

并入之后，"新 tab"里其实有两条不同的购买方式，需要先定节奏：

| 方式 | 确定性 | 耗时 | 占槽 | 定位 |
|---|---|---|---|---|
| **指定采购** | 必得 | 即时到货 | 不占 | 花钱买确定性，但**限量**（每类每日 1–2 件） |
| **目标掠夺** | 随机 | 2–7 天 | 占 | 花时间赌收益，可能出稀有 |

这样"混合"的取舍落在**钱 / 时间 / 确定性**三者的交换上，且保留了现有"点一下就到账"的商店手感；
稀缺性由"限量刷新"提供，而不是给每颗糖果都加等待时间。

如果改成"采购也要等 1–2 天"，体验会更像下军令，但日常消耗品（糖果）会变得繁琐。

### 10.9 新方向：个体作为"任务工具"（讨论中）

> 讨论中提出的方向：**派玩家培育的个体去执行掠夺任务，用个体的类型 / 特性 / 性格 / 能力等 meta 决定它能不能去、去得多好。**
> 目标：让"定向培育符合某种功能的宝可梦"成为经营策略，同时利用物种多样性，并贴合"火箭队把宝可梦当工具"的设定。

#### 为什么这个方向比"出售"有策略

- 出售是"把个体换成资源"，个体本身没有留存价值；任务派工是"个体持续产出"，且**派谁**会改变结果。
- 当任务需求由外部（目标场景）决定时，个体从"可互换的数量"变成"有岗位适配性的人员"。
- 繁育的目标从"多生"变成"生出能干某件事的个体"，闭环变成：
  **看任务需求 → 定向培育 → 派工 → 得道具 → 道具强化个体 → 接更难的活**

#### 设计原则（避免变成无聊玩法）

1. **资格与效率分离**：门槛决定"能不能去"（制造培育目标），效率决定"去得多好"（制造选优空间）。
2. **占用即代价**：任务期间个体不可用于繁育 / 出售 / 实验，形成机会成本。
3. **惩罚要轻**：失败主要是空手、掉耐受、轻伤；不轻易致死（死亡继续集中在实验室）。
4. **不新增系统**：任务只读已有 meta，不引入新资源。
5. **首版极简**：单任务、1–2 个需求标签、不做团队多槽、不做熟练度。

#### 资格维度（已决定）

- ❌ **不用性格**：25 种、池子大、目前没有变更手段，难以定向培育，容易把玩家卡住。
- ✅ **用特性 + 宝可梦分类（种类）**：这两类是与数值基本无关的 meta，适合作为机制门槛，也贴合"火箭队把宝可梦当工具"的设定。
- 注意：分类（genus，如"种子宝可梦"）此前因"没有用处"被整体删除（`fetch-data` 与 `dex.json` 都已剔除），现在要恢复。

#### 数据现状（2026-11-19 核对）

| meta | 分布 | 可观测 | 可定向 |
|---|---|---|---|
| 特性 | 151 物种：1 个的 6 种、2 个的 46 种、3 个的 99 种（含隐藏特性） | ❌ 不显示 | ❌ 随机、不遗传 |
| 分类 | 每物种 1 个（如"种子宝可梦""鸟类宝可梦"） | ❌ 已删除 | ✅ 选物种即定向 |

**结论**：分类天然可定向（选物种）；特性若保持"从 2–3 个里随机"，就会重演性格的问题。
因此在把特性当门槛之前，必须先定它的定向方式（见待定）。

#### 资格 vs 效率（两层）

- **资格（能不能去）**：物种级 meta（特性、分类）——制造"该繁育哪些物种"的目标。
- **效率（去得多好）**：个体级（等级、能力值、特质）——制造"派哪一只更强"的选择。
- 两层分开，既利用物种多样性，又不丢掉个体质量的意义。

#### 一个顺手的价值点：不孕不育

不孕/不育目前是纯负面。若任务系统存在，它们天然适合**高危任务**（没有繁殖价值，派出去不怕损失），
可以把"负面特质"变成"岗位适配"。同理，头目适合硬碰硬的任务，闪光适合需要稀有度的任务。

#### 待定

- [ ] **特性的定向方式**：A. 每物种固定主特性（`abilities[0]`，确定但特性门槛≈物种门槛）／B. 特性可遗传（多一层培育深度，但要先解决显示）／C. 特性胶囊道具（由掠夺产出）
- [ ] 分类字段的恢复方式（重新抓取 / 在 `data.mjs` 加覆盖表）
- [ ] 特性的可观测方式（直接显示 / 随研究进度披露）
- [ ] 任务失败的具体代价（掉多少耐受、是否受伤、是否可能逃跑/死亡）
- [ ] 是否允许多个个体同时执行一个任务（团队制会显著增加复杂度）
- [ ] 任务需求是明确显示还是模糊描述（模糊 → 更贴"研究"，但可能让玩家试错成本过高）

### 10.10 信息披露原则：所有个体信息都跟"研究进度"走

> 讨论确认的大方向：**个体的信息展示与披露，统一挂在物种研究进度上**，以强化"研究"这一行为的存在感。
> 特性此前因为没用被隐藏，现在既然要作为门槛，就恢复显示——但显示时机同样受研究进度控制。

#### 现状的不一致点

- 个体卡片：属性徽章、性格、等级一直显示
- 物种详情：属性、种族值按研究进度隐藏（未研究显示 `？？？`）
- 特性：完全不显示
- 分类：已删除
- 蛋组：另一套规则（繁育确认 / 研究 100% 补全）

同一份信息在"个体"和"物种"两个界面里的可见性不一致，玩家会困惑。

#### 建议：能力值按"解锁序列"逐项披露（草案）

这是**唯一需要测量**的信息，所以它继续按研究进度逐项公开：

```
六项能力值（按种族值从高到低）
```

- 研究进度条 = 测量进度，每约 16.7% 公开一项，100% 全部公开（与现有实现一致）
- 卡片上的 `？？？` 会随着研究推进逐项消失，玩家能感觉到"我越来越认识它了"
- 特性、分类、性格等**不上这条序列**，默认可见（见下）

#### 特性 / 分类：由「组织采样」解锁（已决定）

讨论最终确定：**特性与分类不做"默认可见"，改为行为解锁**。

| 项目 | 规则 |
|---|---|
| **解锁动作** | 对该物种的任意个体**首次完成「组织采样」且该个体存活** |
| **成功率** | 采样过程中个体死亡 **不算解锁**（已决定）；需要换一只再做 |
| **解锁范围** | **物种级**：一次解锁，该物种所有个体都可见分类与其自身特性 |
| **解锁内容** | 分类（种类）+ 特性（个体各自的特性随之可见） |
| **解锁前表现** | 卡片显示"特性未知 / 分类未知" |
| **派工拦截** | **只拦任务点名要求的标签**（已决定）：任务要求特性/分类、而该个体信息未知 → 不能派；任务没要求 → 不拦 |

理由与设定：你是研究员，取样之后才知道它是什么种类、有什么特性；
这也让「组织采样」这个基础实验有了研究之外的实际用途。

#### ⚠ 已知实现问题：有 6 个物种做不了「组织采样」

核对数据（2026-11-19）：专属实验条数分布 `{2:2, 3:143, 4:5, 5:1}`。
`experimentsFor()` 的补入规则是"不足 5 条才从基础三条里补"，具体补入顺序是 `对战 → 采样 → 体测`：

| 专属条数 | 补入内容 | 能否做组织采样 |
|---|---|---|
| 2 | 对战 + 采样 + 体测 | ✅ |
| 3 | 对战 + 采样 | ✅ |
| 4 | 只有对战 | ❌ |
| 5（#003 妙蛙花） | 不补 | ❌ |

也就是说：**5 个 4 条专属的物种 + 妙蛙花，永远无法通过采样解锁特性/分类**。

**已决定采用方案 A：让「组织采样」常驻**——不受补入规则影响，所有物种的实验室里都能看到它。
实施时的副作用：这 6 个物种的实验列表变成 5–6 条，
而"未做过的实验各压 2% 进度上限"的公式（`unperformed × 2%`）需要重新校准。

#### 由此产生的冲突：任务资格依赖"已知信息"

掠夺任务若按特性 / 分类筛人，玩家必须先"认识"这只个体。三种处理（未拍板）：

| 处理 | 效果 |
|---|---|
| **盲派** | 信息未知也能派，靠结果反推（贴"研究"，但试错成本高） |
| **禁止** | 信息未知的个体不能派 → 逼玩家先研究该物种（门槛清晰，但可能卡住） |
| **模糊提示** | 显示"看着像是能派上用场的"之类定性判断，不保证 |

#### 待定

- [x] 任务资格在信息未知时的处理：**拦截**（已决定，见上表）
- [x] 采样过程中个体死亡：**不算解锁**
- [x] 拦截范围：**只拦任务点名要求的标签**
- [ ] ~~**采样可用性**：方案 A（常驻）／方案 B（独立动作）~~ → **已定：方案 A**，注意重算 `unperformed × 2%`
- [ ] 任务界面如何提示"需要先做组织采样"
- [ ] 个体卡片与物种详情的可见性是否要统一到同一套规则

### 10.11 美术：性别立绘（讨论中）

**现状**：`data/sprites/` 里每个物种只有一张 `{id}.png`（默认图），`sprite(id)` 不带性别；
性别只靠卡片上的 `♂ / ♀ / —` 符号区分。抓取脚本也只抓默认图，没有 female 目录。

**事实**：PokeAPI 的 `sprites/pokemon/female/{id}.png` 提供雌性立绘，但**第一世代里有性别差异的物种很少**
（典型如皮卡丘的尾巴缺口），其余多为第四世代之后才追加的差异。

**讨论结论（未拍板）**：

- 卡片上的立绘只有约 64px，细微差异（尾巴缺口之类）很可能看不清；性别符号仍然是更可靠的识别方式。
- 若要做，正确做法是**只补确有差异的少数物种**，并让 `sprite(id, gender)` 在缺失时回退默认图，
  不要为了统一给 151 个物种都放大一套 female 图。
- 视觉差异属于"一眼看到"的观察，**不应受研究进度限制**（与研究解锁的是"知识"，不是"外观"）。

- [ ] 是否加入性别立绘；若加，先确认第一世代实际有差异的物种清单
- [ ] 是否需要"熟练度/专精"（建议首版不做）

### 10.13 v1 范围调整：先做金币商店（2026-11-20）

| # | 决定 | 内容 |
|---|---|---|
| 10-9 | ✅ **v1 只做金币商店** | 道具全部并入一个商店、用资金购买；**不做掠夺任务** |
| 10-10 | 🕒 **任务那套整体暂缓** | §10.3 / §10.9 / §10.12 的据点、岗位、文案模板、效率层全部保留为**以后的设计底稿**：不实施、不删 |

理由：

- 道具系统（容器 + 获取渠道）本身可以先立起来，不依赖任务。
- 但任务的价值（效率层、产出消费端）依赖还没定的系统，现在做等于给空循环加装饰。
- 先把商店做出来，等个体价值/消费端有结论，再把商店改造成"物资 / 掠夺"的设定形态。

## 11. 实验室与研究（讨论中）

### 11.1 现状数字与痛点

- 研究需求 = `40 + (255 − 捕获率) × 1.4`：烈雀 40、皮卡丘 131、化石翼龙 334、超梦 393
- 一轮实验（5–8 条各做一次）约给 30–40 点进度 → 稀有物种约需 10 轮、**60–80 次点击**
- harsh 档一次损耗约 110 点耐受 → Lv.1 个体一击即死
- 物种研究 100% 后：只剩最伤身那条实验，不再记日志，实验室对该物种基本失去意义

三个结构性问题：

1. **决策不可见**：成本只标资金，耐受损耗与进度收益都隐藏，玩家只能凭经验记，谈不上权衡
2. **产出单一且一次性**：只产出"研究进度"，100% 后变成真空
3. **物种同质**：458 条专属实验只是文案不同，机制都是三档，151 次体验高度重复

### 11.2 新方向：满研究后转为"献祭式产出"

讨论确定的方向（**先只做产出端，消费端以后再说**）：

| 项目 | 决定 |
|---|---|
| **动作名称** | **「终末榨取」**（四个字；文案里不再出现"实验"） |
| **可用动作** | 研究 100% 后，只保留 **1 条终末榨取**（原计划 5 条极端实验，为避免铺开缩减） |
| **样本结局** | 这条动作**一次就耗死样本**（必死，不留活口） |
| **产物数量** | 由样本的**当前耐受度**决定，再叠加随机影响（正态分布） |
| **产物种类** | 先只做 **1 种产物**（不做 5 种） |
| **消费端** | 暂不设计（后续再定：加速研究 / 研究部订单 / 其他） |

### 11.3 产物公式草案（正态分布）

讨论确定：**产物数量用正态分布**——大多数情况落在平均数附近，少数情况会明显偏多（或偏少）。

参数建议：

```
μ = max(1, 当前耐受 / 50)       // 平均产出，随耐受提升（2026-11-20 由 /35 改为 /50，对齐克隆成本）
σ = max(0.6, μ × 0.3)           // 波动幅度
数量 = clamp(round(正态(μ, σ)), 1, 上限)
```

概率表现（σ = 0.3μ）：

| 样本耐受 | μ | 常见区间（±1σ） | 偶尔偏多（≥μ+2σ） | 极罕见（≥μ+3σ） |
|---|---|---|---|---|
| 100 | 2.0 | 1–3 | 3–4 | 5 |
| 158 | 3.2 | 2–4 | 5–6 | 7 |
| 218 | 4.4 | 3–6 | 7–8 | 9+ |
| 273 | 5.5 | 4–7 | 9 | 11 |

**为什么是 /50**：纯复制一只克隆体要 4 份样本。用 /35 时 Lv.60 能榨 6 份，等于“榨一只造一只半”，会变成印钞机；用 /50 时约 4.4 份，正好一只换一只。

实现说明：游戏用的是种子化 LCG，取两次 `random()` 做 Box–Muller（或四次均匀数叠加近似正态）即可，
仍然是可复现的确定性随机。

设计要点：

- 用**当前剩余耐受**而不是上限：先拿去繁育/实验过的个体，献祭时产物更少 → "留着献祭还是先用"成为取舍
- **正态的尾巴是对称的**：偶尔也会明显偏少。**已决定：暂不保底**，先按完整正态跑，后续按游玩体验再调整
- 上限要设，否则极端值会失控（建议 ≤ 2μ，待定）

| 项目 | 决定 | 理由 |
|---|---|---|
| **实验条数** | **保留 5–8 条** | 重复执行已经秒结算，多点几下成本低；458 条专属实验的内容不浪费 |

| **递减收益** | **不做** | 实验室的选择被定义为**效率题**：harsh 永远最优，这是设计而不是缺陷 |
| **"各做一次才能到 100%"** | 保留（现有 `未做数 × 2%` 上限） | 唯一还保证其他实验被看到一次的东西 |

| **重复执行的结果卡** | 删除，只写一条日志 | 玩家第三轮之后不会读；文案留在日志里可回看 |
| **实验日志逻辑** | **不改**：每次实验（含重复）照常写入研究笔记的实验日志 | 实验体很少能熬过 10 次实验；玩家倾向最高档时，1–2 次就会把一只用死，日志量不会失控 |
| **首次执行** | 保留加载条 + 完整结果卡 | 仪式感与物种风味集中在这里 |
| **死亡 / 研究完成** | 总是弹卡 + 日志高亮 | 重要事件必须被看见 |

#### 为什么保留冷却（讨论记录）

原本冷却的作用是"防止玩家只做压力最大的实验"。但按现值算，**资源效率最高的其实是 gentle**，
harsh 的优势只是"每次点击给得多"；而个体过剩时，玩家不在乎消耗，所以效率最优就是 harsh。
这个"玩家总选最高档"的现象无法用递减收益纠正（递减只会让玩家改成两个按钮轮流点），
因此决定：**接受效率题的本质，把冷却保留下来作为节奏控制，其余摩擦全部去掉**。

### 12.5 金币来源核对：繁育 → 出售（2026-11-20，实测反馈）

> 玩家实测：**金币很容易获取，一直"繁育 → 出售"就够了**。这条推翻 §12.4 的收入模型（那里只算了订单）。

| 环节 | 数字（以烈雀为例） |
|---|---|
| `valueOf` | 200 + bst×0.9 + (255−捕获率)×1.2 = **436** |
| 卖价 Lv.1 / Lv.60 | 0.85~1.75 倍系数 × 0.45 → **170 / 343** |
| 育种成本 | **0 金**，只占栏位 30 秒（母体耐受 −32） |
| 孵化 | 24–120 秒，蛋位 2–5 |
| 吞吐 | 早期约 2 只/分 → **340 金/分**；后期约 7 只/分 → **1,200 金/分** |
| 9 小时累计 | 约 **18 万 – 64 万金** |

**结论**：出售**无门槛、无上限、接近被动**，所以它成了最优解。订单被降级成"顺手交一下"，职级 5 万、研究 48 万都能这样刷出来。

## 13. 繁育的设定定位（2026-11-20，✅ 已认可）

> **培育栏是产线也是样本库：母体是耗材，蛋是货，也是实验材料；每只子代都要决定归组织还是归你。**

### 13.1 为什么是这个定位

- **抢来的货不可持续**：图鉴 151 个、订单每天要人，靠蛋贩子和抢，供给是断的。繁殖是唯一"自己造"的环节——组织眼里它是**资产自我复制**，不是照顾宝可梦。
- **研究需要样本量**：抢来的每一只都是孤本，做不了对照、复不了现。**繁育是博士唯一能造出"第二只同种"的办法。**
- **代价必须有**：母体耐受 −32、Lv.1 只能产 3 只、力竭即死——这三条已在代码里，正好构成"工业"的残酷感。

### 13.2 三个视角 → 三个机制落点

| 视角 | 看到的繁育 | 评价标准 | 机制落点 |
|---|---|---|---|
| **组织** | 资产自我复制 | 数量、等级、物种对口 | 批量订单（后勤部一次要 5 只一般系） |
| **你** | 样本供应 | 同种几只、能不能对比、体格 | 研究部订单（要 3 只同种做对照） |
| **代价** | 母体是耗材 | 还能产几只 | 母体耐受在栏位可见、力竭死 |

两个订单形态都复用现有订单系统（多一个 `qty` 与一种需求类型），不新开。

### 13.3 核心动作是"分岔"，不是"配种"

| 去处 | 换来什么 | 失去什么 |
|---|---|---|
| 交组织（订单） | 资金 + 声望 | 这只再也见不到 |
| 送实验室 | 研究进度（第 N 个样本） | 大概率死在台上 |
| 留下当种 | 下一轮的亲本 | 占栏位、耗空间 |
| 卖黑市 | 现金 | 价格最低、没有声望 |

这四个去处**界面里都已经有了**。缺的不是按钮，是"个体之间有差异"和"每个去处读不同的维度"。近亲把这个决定拉长：留种最快的是自交，但后代越来越脆；要长期就得买外血。

### 13.4 这个定位排除什么

- ❌ 不做亲密度 / 羁绊（README 已声明）——培育栏里没有温情，只有耐受度和产线。
- ❌ 不做"保育"叙事——你是被"请"进来的。
- ❌ 不做随机出稀有——稀有感来自体格与血统，不是抽卡。

### 13.5 落地顺序（建议）

1. **表达层**：让"产线/样本库"被看见（母体产能、体格、血统）
2. **机制层**：近亲 K2、配种意图
3. **出口层**：各去处读不同维度（订单读等级/物种、黑市读体格……）

### 13.6 体格（🕒 2026-11-20 决定：先不做）

讨论过甲、乙两案（星级直接由 IV 算 / 由已披露的能力值推导），**最终决定先不做体格机制**。

替代方案：**研究 100% 后，个体详情直接给出六项 IV 的具体数值。**

| | 保留 | 放弃 |
|---|---|---|
| 知识阶梯 | 研究 → 认识个体 | 卡片/列表层面的星级快速比较 |
| 认知节奏 | 未研究时仍是 `？？？` | 部分披露时的中间反馈 |

**代价**：挑亲本只能打开详情看数值；只有研究透的物种才谈得上"聪明地育"。这与"繁育是样本库、只对少数物种建品系"的定位是一致的。

**数据没丢**：`mon.ivs` 完整保留，以后想再起体格不需要改结构。

### 13.7 近亲与体质（✅ 2026-11-20 已定）

#### 先立住前提：近亲是有收益的

回交能把优等基因快速固定下来——这是现实育种的标准手段，不是偷懒。单项 IV 举例：

| 配对 | 子代均值 |
|---|---|
| 优等（28）× 它的子代（20）＝回交 | **24**（区间 19–29） |
| 优等（28）× 市场外血（15） | 21.5（区间 16.5–26.5） |

所以近亲不是纯惩罚：**提纯快，但体质退化**。这才构成取舍。

#### 决定

| # | 决定 | 内容 |
|---|---|---|
| 13-1 | ✅ **代价落在“体质”**（2026-11-24 改为分级） | 非近亲 = `双亲均值 + 0.2`，封顶 1；近亲 = `min(双亲) × 乘数`，下限 **0.5** |
| 13-1a | ✅ **乘数按关系远近分级** | 直系 **0.70**（任意代）／同胞 **0.78**／叔侄·表亲 **0.88**／二代表亲 **0.95**／三代以外 **不惩罚** |
| 13-1b | ✅ **判定：直系优先，旁系看深度** | **直系**：一方在另一方的祖先表里，**不看深度**（隔多少代都一样狠）。**旁系**：取所有共同祖先里 `max(双方深度)` 的最小值 |
| 13-1c | ✅ **标记与惩罚同步** | 乘数 **≤ 0.95 才显示「近亲」**；三代以外不惩罚、也不显示。标记仍只有一个词，不做分级（§14.6 不变） |
| 13-2 | ✅ **系数乘在耐受上限上** | 不新增 UI，体现为已有的耐受灰度变短 |
| 13-3 | ✅ **死胎与系数绑定** | 系数 ≥0.85 时 **0%**；0.72 → 2%；0.61 → 4%；0.50 → 6%。死胎照常消耗母体 **40** 耐受 |
| 13-4 | ✅ **开局 3 只** | 波波♂ + 烈雀♀ + 烈雀♀（后两只无亲缘）。**两只雌性必须是同一物种**，否则断线风险不会下降（见下） |
| 13-5 | 🕒 **断代保护暂缓** | “无任何可繁育个体时市场必出百变怪”——设计认可，但实现复杂度与触发频率不划算，记为以后 |

#### 分级乘数表（2026-11-24）

```
直系 0.70  ──  同胞 0.78  ──  叔侄·表亲 0.88  ──  二代表亲 0.95  ──  三代以外 无惩罚
   ↑ 两代就废                    ↑ 六代                 ↑ 十三代
```

| 关系 | 深度 | 乘数 | 显示「近亲」 |
|---|---|---|---|
| 直系（亲子 / 祖孙 / 曾祖孙…） | 任意 | 0.70 | ✅ |
| 全同胞 / 半同胞 | 1 | 0.78 | ✅ |
| 叔侄 / 表亲 | 2 | 0.88 | ✅ |
| 二代表亲 | 3 | 0.95 | ✅（阈值上） |
| 三代以外 | ≥4 | 不惩罚 | ❌ |

**为什么直系不看深度**：隔两代、五代的直系亲属，在直觉和遗传上仍然是同一回事——它是“血统没有分叉”，不该因为代数变远而变轻。旁系不同，交叉得越远越接近“没有关系”。

#### 系数对照（已计入“栏位内升级回补耐受”与“产下最后一胎再死”）

| 系数 | Lv.1 雌性上限 | 实际能产几胎 | 死胎率 |
|---|---|---|---|
| 1.00（外血） | 100 | **3** | 0% |
| 0.85 | 85 | 3 | 0% |
| 0.78 | 78 | 2 | 2% |
| 0.72 | 72 | 2 | 2% |
| 0.61 | 61 | 2 | 4% |
| 0.50（触底） | 50 | 2 | 6% |

#### 连续这样配的衰减速度

| 配对方式 | 乘数 | 第1代 | 第2代 | 第3代 | 第4代 | 第5代 | 触底 |
|---|---|---|---|---|---|---|---|
| **一直亲子回交** | 0.70 | 0.70 | **0.49→0.50** | 0.50 | 0.50 | 0.50 | **2 代** |
| 一直全同胞 | 0.78 | 0.78 | 0.61 | 0.50 | 0.50 | 0.50 | 3 代 |
| 一直叔侄 / 表亲 | 0.88 | 0.88 | 0.77 | 0.68 | 0.60 | 0.53 | 6 代 |
| 一直二代表亲 | 0.95 | 0.95 | 0.90 | 0.86 | 0.81 | 0.77 | 13 代 |

#### 数据结构的连带改动

现在的 `ancestors` 是**平铺的 uid 数组**，没有深度，无法区分“父亲”和“曾祖父”。要支持分级判定，得改成记录最近代数：

```
ancestors: { [uid]: depth }     // 该祖先到我的最近代数
```

| 判定 | 算法 |
|---|---|
| 直系 | 对方的 uid 出现在我的 depth map 里（任意深度） |
| 同胞 | 双方 depth=1 的祖先有交集（共享父母） |
| 旁系深度 | 共同祖先里 `max(我的depth, 他的depth)` 的最小值 |

涉及 `lineageOf`、`isKin`、`createEgg`、`createMon` 与存档结构。**没有向后兼容**，旧存档直接作废。

⚠ 注意：**“能产几胎”不是常数**。培育栏同时给被动经验（26/秒），母体在产仔过程中升级，而升级会把耐受上限的增量补回给她。所以先养到高等级再配，产量更高；等级越高，近亲惩罚的绝对影响越小。

#### 为什么不做这两种

- ❌ **不做耐受税**（K2 的 32→48）：近亲在现状里是默认路径（同种外血几乎买不到），加税等于全体产能 −25%，玩家没有替代方案，是罚款不是选择。
- ❌ **不做随机畸形率**：与“可复现的规律”的基调不符。死胎是体质差的自然表现，玩家能算出来，这才写进笔记。

#### 启动容错

原担心：开局只有一个母体，3 胎全雄（12.5%）就断线。
解法不是“给个体翻倍体质”（耐受是全局资源，翻倍会连带影响实验室，且设定上说不通），而是**多给一只同物种的雌性**：

- 两只烈雀♀ → 该物种 6 胎，全雄概率从 12.5% 降到 **1.56%**
- 注意：**两只雌性必须同物种**。若一只烈雀♀、一只超音蝠♀，则每条线仍只有 3 胎，断线风险不变，只是多了个物种。
- 保留波波♂ 作父本，还能顺带教会玩家“子代随母方”（波波 × 烈雀 → 烈雀）
- 设定上说得通：**基地配发的第一批样本是三只**

### 13.9 同性配对的设计意图（2026-11-20）

> ⚠ **本节已被 2026-11-24 的决定取代。**原方案是“同性配对 = 玩家主动的恶，游戏要给回应（争斗死一只）”。新决定更干脆：**两只同性的个体不允许放进同一个培育栏**，入口就拦住；`compatibility` 的 `same-sex` 分支、`fightToleranceLoss`、争斗文案与统计全部删除。下面的内容仅作为设计过程的记录保留。

> 繁育是一公一母的配对。玩家刻意放进两公或两母，说明他有额外的想法——这个行为被定义为**“主动的恶”**，游戏应当反馈它。

现状：同性配对与蛋组不匹配共用同一条结算路径（争斗 → 弱者死），只是原因文案不同。所以它读起来像系统判定，不像“它对你的回应”。

待展开的方向（未拍板）：

- 结果文案专属化：同性配对不该复用“争斗中伤重不治”。
- 明确“没有产出”：它不产生任何数据——这是研究员自己的评价标准，不是道德指责。
- 行为被记录：重复这样做会在研究笔记里留下痕迹。
- 数值是否仍为“死一只”，待定。

### 13.10 内部循环收口（2026-11-20）

按「放入 → 等待 → 结算 → 蛋 → 孵化 → 接班」走了一遍：

| # | 环节 | 决定 |
|---|---|---|
| 1 | 力竭结算 | ✅ **产下最后一胎再死**（不再"白等一轮然后死"） |
| 2 | 养成耦合 | ✅ **承认现状，暂不调整**：栏位内升级会回补耐受，母体越养越能生。这是巧合不是设计，但先按简单做法跑 |
| 3 | 孵化反馈 | ✅ 普通孵化只进日志；**只有异常才强调**（虚弱、不孕、闪光、首次孵出该物种），避免批量繁育被打断 |

其余环节的结论：

| 环节 | 结论 |
|---|---|
| 放入 | 保持“只能填空栏位”，不加栏位间移动 |
| 选择器 | 显示物种、性别、等级、性格、已知蛋组、近亲标记、不孕标记；**不显示“能不能配”**（博士只能靠试） |
| 蛋位满 | 栏位写明「孵化器已满」，别让条停着不说话 |
| 蛋卡 | 物种 + 剩余天数；父母/来源点开再看 |
| 接班 | **不需要谱系 UI**——玩家只要在选择器里看到「近亲」就够（§14.5） |

已知但暂不处理：

- 近亲惩罚被等级稀释（Lv.60 母体 ×0.5 仍有 109 耐受上限）。
- “先养到高等级再配”成为最优解——耦合的副作用，不是设计目标。

### 13.12 入口与蛋的处理（2026-11-24）

#### 同性配对：入口拦截

| 变更 | 内容 |
|---|---|
| 选择器 | **不做校验、不做置灰**：只把**同性**个体从列表里去掉。空栏位列出全部；已放入一方时，去掉与它同性的那些——**异性、无性别、百变怪照常列出** |
| `compatibility` | 删除 `same-sex` 分支 |
| 争斗机制 | **整体删除**：`fightToleranceLoss`、`stats.fights`、争斗文案、相关测试一并移除 |
| 百变怪例外 | 百变怪可与任意性别配，不受此规则限制 |
| §13.9 | 整节作废（原文保留作过程记录） |

**为什么是“不展示”而不是“置灰”**：置灰等于告诉玩家“这里本来有个选项，但你不能用”——那是在解释一个不存在的选择。不展示，玩家根本不会意识到有这回事，也就不需要任何说明（§14.7）。

**为什么不再给“回应”**：争斗原本是“玩家刻意把两只同性放一起”的反馈。现在入口就拦住，玩家根本没有机会表达这个意图——**没有输入，就不需要回应**。

⚠ 连带影响：争斗删除后，繁育里唯一“会死人”的路径只剩**力竭**；`weakerOf` 只剩围栏霸凌在用。

#### 蛋：不能丢、不能卖，只等孵化

| 项 | 结论 |
|---|---|
| 丢弃 / 出售 | **没有入口**，蛋只能孵 |
| 蛋位满 | 栏位显示「孵化器已满」，进度停在 2.5 天，**不惩罚** |
| UI | **待简化**：现在是 立绘 + 物种 + IV + 性格 + 进度条；计划只留 **物种 + 剩余天数**，父母/来源点开再看 |

**为什么不给“丢弃”**：蛋是繁育唯一的产出。可丢弃就等于可“重摇”——玩家会为了刷性格/IV 反复生、反复丢。**必须孵出来**（占一个围栏位置、要处理），才构成真实的产能压力。

## 14. 界面信息原则（2026-11-20，✅ 已定）

> **信息跟着决策走：数据全量保留，界面只给"此刻要做决定时用得上的那几项"。**

### 14.1 三层

| 层 | 存/放什么 | 界面怎么用 |
|---|---|---|
| **数据层** | 全部保留（IV、蛋组、血统、耐受、来源……），逻辑随时可读 | 不管 |
| **决策点** | 做选择的那一刻，把相关字段推到眼前 | 选择器、对比、排序 |
| **默认视图** | 只留"不看就会做错"的少数几项 | 卡片 |

### 14.2 判定标准

**玩家此刻能不能基于它做出不同的选择？不能，就不显示。**

同一个字段在不同场景地位不同：蛋组在"选谁放进栏位"时是必需品，放进去之后就是噪音。

### 14.3 已应用

| 场景 | 决定 |
|---|---|
| 繁育栏卡片 | 删属性徽章、经验条；蛋组移到"选择放谁"的选择器；编号弱化 |
| 耐受度 | **已有灰度展示**，足以表达"母体还能不能撑"，不再加数字 |
| 个体详情（研究 100% 后） | **直接给出六项 IV 的具体数值** |

### 14.4 推论

- 隐性设定保护的是**没研究过的东西**；一旦研究完，具体数值可以直接给。
- **界面克制 ≠ 隐藏信息**：信息应当可获得，只是不必随时铺开铺满。
- 新加任何字段时先问：它属于数据层、决策点，还是默认视图？默认先放数据层，别默认放卡片。

### 14.5 复杂度原则（2026-11-20，✅ 已定）

> **逻辑可以复杂，操作必须简单。复杂度放进系统里，不放到玩家手上。**

| 层 | 可以有多复杂 | 玩家接触到的 |
|---|---|---|
| 血缘 | 祖先表、共同祖先、代数、体质系数、杂交优势 | 只看到「近亲」两个字 |
| 体质 | 0.85 衰减、杂种优势、封顶 | 只看到耐受灰度更短 |
| 遗传 | 六项均值 ±5、性格 50/50、死胎概率 | 只看到孵出来的结果 |
| 判定 | 任意深 | 只在需要时给结果 |

**推论**：

- 任何新机制都必须回答一句：**玩家会因此多做几个动作？** 如果是“每次都要多做一步”，就砍掉或改成自动。
- 玩家永远不需要查谱系、算系数、记代数。**如果他必须查表才能玩对，就是设计失败。**
- 已经通过“选哪两只”表达了的意图，不再额外加一个下拉。

### 14.6 由此砍掉的两项

| 项 | 处理 |
|---|---|
| 近亲标记分级（亲子/兄妹 vs 祖孙/表亲） | ❌ **不做**，只给一个「近亲」标记——分级会逼玩家按远近做不同决策 |
| 配种意图（像父 / 像母 / 求稳） | ❌ **不做**——“想要什么”已经通过“选谁做亲本”表达了，再加下拉是每次配种多一步 |

### 14.7 文案规则（2026-11-20）

> **界面文字只写「它是什么 / 它做了什么」，不写「为什么」和「你该怎么做」。**

这条是对 §14 的补充，针对一个反复出现的坏习惯：每加一个机制，就顺手加一句解释。

**禁用**：

- 「要……才……」「先……再……」「注意」「建议」「⚠」
- 对机制的自我解释（"耐受越高，留下的东西越多"）
- 教学句（"要判断这只好不好，先把这个物种研究完"）

**允许**：

- 名词标签：繁殖 / 耐受 / 编号 / 未知
- 状态词：已完成 / 已确认不合 / 未编号
- 结果句：发生了什么
- 世界观文案：实验描述、处置正文（这些是内容，不是说明）

**判定方法**：删掉这句，玩家会不会**误判发生了什么**？会，保留；只是告诉他“该怎么想、该怎么做”，删。

**已删的实例**：

| 原文 | 位置 |
|---|---|
| 「⚠ 样本会被用尽 · 耐受越高，留下的东西越多」 | 终末榨取卡 |
| 「要判断这只好不好，先把这个物种研究完」 | 个体详情（体格方案，已砍） |

## 15. 设定基调（2026-11-20，✅ 已定）

| # | 决定 | 内容 |
|---|---|---|
| 15-1 | ✅ **玩家不是卧底** | 他是**自愿留下、清醒计算过代价的理性人**，不是被迫者，也不暗中反抗 |
| 15-2 | ✅ **他知道这是恶** | 但他判断这些研究成果能为世界带来更大的东西。他不辩解，也不忏悔 |
| 15-3 | ✅ **研究笔记不是罪证** | 那是正作里奠定人类认知的那本书。他用这座地下室和这些个体写成了它 |
| 15-4 | ✅ **不拟人、不煽情、不指责** | 宝可梦没有"抗拒""亲密"的表现。残忍来自**效率与冷漠**，不来自展演——写"它被拖出来"比写"它哀鸣着"更冷 |
| 15-5 | ✅ **游戏不评判玩家** | 只把代价摆在面前，不给道德提示 |

### 15.1 旧理解 vs 更正

| | 旧（错） | 新 |
|---|---|---|
| 身份 | 卧底、暗中反抗 | 自愿的合作者，清醒的共谋 |
| 动机 | 留证据、等时机 | 只有这里的样本与设备，才写得成那本书 |
| 情绪 | 隐瞒、不安 | 冷静、算过账、不解释 |
| 调子 | "组织不知道" | "我知道，我选择" |

### 15.2 需要同步修改的现有文案

现在的开场白与 README 还是旧理解：

> 「你是年轻的大木博士，被"请"进火箭队的地下基地：替他们管理与运营抢来的宝可梦，同时**偷偷记录**每一只的数据……」

"被请"与"偷偷"都与基调冲突。建议改成：

> 「你是年轻的大木博士。你自愿留在这座地下基地——外面的世界不会给你这些样本，也不会给你这些设备。代价你清楚，你付得起。」

### 15.3 残忍该放在哪里

**不放在形容词里，放在数字里。** 现有的"母体 100 耐受、每胎 −32、三胎力竭而死"本身就是最狠的一句，不需要再加任何形容。

## 16. 样本、复刻与传说宝可梦（2026-11-20，讨论中）

### 16.1 传说宝可梦：每只一个专属任务（✅ 方向）

| # | 决定 | 内容 |
|---|---|---|
| 16-1 | ✅ **传说不进繁育/市场/复刻** | 每只传说单独设计一个获取玩法（任务），因为它们足够特殊 |
| 16-2 | 🕒 **暂缓实施** | 工作量预估较大，先把方向记下来 |

**现状事实**：5 只传说/幻兽（急冻鸟 144 / 闪电鸟 145 / 火焰鸟 146 / 超梦 150 / 梦幻 151）**目前完全无法获得**——市场排除了 legendary/mythical，它们又是「未发现蛋组」无法繁育。
所以现在**图鉴收束是不可达的**，唯一通关路径是最高职级。

### 16.2 样本：物种绑定，不做通用研究进度（✅ 方向）

曾考虑"样本 = 通用研究进度"，用于救济稀有物种。放弃，原因是：

- **任何分类内都有便宜物种**——按属性、按进化链、按稀有度分档，都只是把套利窗口缩小，不能根除。
- 彻底的解法是绑到具体物种，但那样就失去了"救济稀有物种"的功能。
- **通用性 = 能救济稀有物种，也 = 能被廉价物种套利。** 这是个结构取舍，不是分类精度问题。

### 16.3 外部参考（成熟游戏怎么做）

| 模式 | 代表 | 做法 |
|---|---|---|
| 币按谱系绑定 | Pokémon GO 糖果 | 只给该进化链，烈雀糖换不到超梦 |
| 进度按物种累计 | Palworld 捕获数 | 同种抓够 N 只 → 该物种永久加成 |
| 通用币分层 | Factorio 科技包 | 红/绿/蓝/紫/黄瓶，高级科技只吃高级瓶 |
| 通用币分科 | Stellaris | 物理/社会/工程三池，永不互通 |
| 没有币只有配方 | Subnautica 碎片 / 怪物猎人素材 | 每个蓝图只认自己的碎片/素材 |
| 通用币只给折扣 | 文明 6 尤里卡 | 只打折，不免除 |
| 通用币 + 硬门槛 | XCOM 尸体 | 再有钱也得先拿到那份尸体 |

**共同点**：没有一款成熟游戏给"一种样本全免别的物种研究"；业界靠"不给通用性"或"只给折扣"解决。

### 16.4 克隆：用样本“定制”个体（讨论中，2026-11-20 方向已定）

> 设定：这不是宝可梦，是**火箭队造出来的东西**——制式产品，没有父母，也没有名字。

| # | 决定 | 内容 |
|---|---|---|
| 16-3 | ✅ **样本按物种绑定** | 烈雀样本只能造烈雀；不跨物种、不做通用研究进度 |
| 16-4 | ✅ **定制程度决定花费** | 定制项越多，样本花费越高（幂级） |
| 16-5 | ✅ **克隆体不孕不育** | 硬锁：不能进繁育。定位为道具，不是活体资产 |
| 16-6 | ✅ **克隆体体质 0.85** | 比正常低，但不是残废 |
| 16-7 | ✅ **能交单** | 可以交付部门订单（因此定制“性格”有实际价值） |

#### 规格草案

| 项 | 建议 |
|---|---|
| 个体值 | **固定中庸**（各项 15）——制式产品都是标品 |
| 来源标记 | 「制式」；来源文案写成编号式（“从 6 份烈雀样本里长出来的”） |
| 初始等级 | Lv.1（需要自己养到订单要求的等级） |
| 出售 | 可卖，但价格低——它值钱的地方是“符合需求”，不是“品相” |

| 定制程度 | 样本花费 |
|---|---|
| 纯复制（不定制） | 4 |
| 定 1 项（特性 / 性格 / 性别） | 8 |
| 定 2 项 | 16 |
| 定 3 项 | 32 |

#### 一条硬约束：不能变成印钞机

**“榨一只 → 造一只”必须亏本或刚好打平。**

按 `终末榨取 μ = 耐受 / 50`（Lv.60 约 4 份样本）算：纯复制花 4 份 = 刚好一只换一只；定制一项要 8 份 = 两只换一只。这样克隆的卖点是**省时间**（不用刷性格），不是**赚钱**。

如果样本产出高于克隆成本，就会出现“一只个体变多只商品”的无限循环，会盖过所有其他经济设计。

#### 待定

- [ ] 样本来源：目前只有「终末榨取」（要求该物种 100%）。是否让“实验致死”也给样本？
- [ ] 克隆体能不能出售（倾向可以，但价格低）
- [ ] 定制项最终保留哪几项（性别目前没有任何系统读取）

## 17. 渐进解锁（2026-11-20，✅ 方向已定，细节待定）

> **系统按“玩家的理解速度”解锁，而不是按“内容清单”一次性铺开。**

- 目的 1：避免开局就被一堆玩法淹没。
- 目的 2：贴合设定——你在火箭队里慢慢壮大、升职，才管得到更多事务。

### 17.1 两个天然载体（都已存在）

| 载体 | 是什么 | 已有实例 |
|---|---|---|
| **职级（权限）** | 组织允许你管更多事 | 6 级：声望 18/36/55/75/92，费用 1000/2800/6500/14000/26000；设施升级已有 rankReq |
| **行为（知识）** | 你亲手做过，才懂得怎么用 | 蛋组（繁育成功才揭示）、特性/分类（组织采样存活）、研究 100%（显示 IV） |

所以这不是新系统，是**把已有的门槛当成解锁系统来用**。

### 17.2 混合模型（✅ 2026-11-20 已定）

> **职级给「权限」，行为给「知识」。**

| 轴 | 含义 | 承担什么 |
|---|---|---|
| **职级（权限）** | 组织允许你接触什么——资源是组织给的 | 实验室（实验台是升职奖励）、设施升级、蛋贩子/商店渠道、传说任务 |
| **行为 / 研究（知识）** | 你亲手做到过，才真正掌握 | 蛋组（繁育成功）、特性/分类（组织采样存活）、IV（研究 100%）、终末榨取、**克隆** |

### 17.3 克隆的解锁：走知识轴

- **第一个物种研究到 100% → 解锁「克隆」技术**
- 之后只能克隆**已研究完**的物种——样本本身也只有这条路能拿到
- 设定：克隆是火箭队的机密技术，但**掌握它的是知识，不是职级**

### 17.4 声望问题：渐进解锁最薄弱的一环

现状：**声望只有一个来源（交付订单，+4 / +13）**，而职级是解锁的主轴之一。于是：

- 想升职级 → 只能刷订单
- 研究做得再深，对职级零贡献
- 两条进度线互不相通（§12.3 的 P0）

**建议：研究完成一个物种，给少量声望（如 +2）。**

- 让“职级”和“研究”两条线自然同步：研究快的人，职级也跟着涨
- 同时修掉 P0「研究是纯消耗」
- 需要重算节奏：92 声望 = 23 单，或 46 个研究完成的物种

### 17.5 草案（未定稿）

| 阶段 | 新解锁 | 轴 |
|---|---|---|
| **开局** | 培育栏、孵化、围栏、出售、**部门订单**、蛋贩子、研究笔记（只看得到 151 的目标） | — |
| 职级 1 · 助理研究员 | 进化（石头 / 电缆）、设施升级 | 权限 |
| 职级 2 · 研究员 | **实验室**（研究进度、能力值披露） | 权限 |
| **第一个物种研究到 100%** | **终末榨取**（可以处置该物种的个体） | 知识 |
| **第一次榨出样本** | **克隆（制式生产）** | 知识 |
| 职级 3–5 | 设施上限（已有 rankReq）+ 传说任务（未设计）+ 终局 | 权限 |

克隆因此走的是“行为链”：研究 100% → 会榨 → 有样本 → 会克隆。三件事都是**你做过才知道能做什么**。

### 17.6 三个要小心的地方

1. **早期会变薄**：解锁前，玩家手上只有繁育 + 卖 + 交单。前 10–15 分钟必须有足够的事做，否则不是“不晕”，是“无聊”。
2. **解锁时刻要有仪式**：不能只是导航栏多一个图标。至少是一张卡片 + 一条日志，说明“组织现在允许你……”。
3. **会挤压目标时长**：实验室若在职级 2（约 25 分钟）解锁，研究线就只剩 8.5 小时——要和 9 小时的预算重新对齐。

### 17.7 待定

- [x] 混合模型：职级给权限、行为给知识
- [x] 克隆走知识轴（首个物种 100% → 榨取 → 克隆）
- [ ] 声望是否要给研究加来源（建议 +2 / 物种）
- [ ] 各系统的具体解锁节点
- [ ] 未解锁内容是“隐藏”还是“显示为锁定”
- [ ] 解锁节奏对 8–10 小时预算的影响

## 18. 实验室助手（2026-11-20，✅ 已定）

> 把“点击器”改成“投放”：玩家亲手做发现，助手做重复。

| # | 决定 | 内容 |
|---|---|---|
| 18-1 | ✅ **独立解锁** | 「实验室助手」是一个解锁项（草案：职级 3 · 高级研究员） |
| 18-2 | ✅ **自动的前提：先把该物种亲手做完** | 一个物种的 **5 条实验全部亲手做过**，才算“亲自处理过”；在此之前助手不会碰这个物种 |
| 18-3 | ✅ **连续 tick，不是离散点击** | 耐受按秒下降、进度按秒上升、耗材按秒扣钱；UI 显示「助手研究中」 |
| 18-4 | ✅ **暂时只有 1 个助手** | 一个助手只负责一个实验体；后期可升级为多个 |
| 18-5 | ✅ **打断 = 玩家接管** | 打断后助手让位、在旁边观摩（仍占用）；玩家可以亲手做这个物种的任意实验，也可以随时把自动交还给助手 |
| 18-6 | ✅ **到 100% 自动停，但仍占用** | 研究完成不等于收工——要等玩家处置这只个体，助手才释放 |
| 18-7 | ✅ **实验体必死** | 入台即判死。实验室没有出口，只有死亡或“处理”（现状本来如此） |

### 18.1 数字（对齐 harsh 档）

| 资源 | 速率 |
|---|---|
| 研究进度 | **0.5 点/秒** |
| 耐受损耗 | **3.86 点/秒** |
| 实验耗材 | **6.4 金/秒**（12.9 金/进度点） |

一个助手 ≈ 0.5 进度/秒；全图鉴 37,499 点 = **20.8 小时**。所以单个助手是“第 5 台免费实验台”，**是补充不是替代**；玩家同时手动跑 4 台时总吞吐约 2.5 点/秒，全图鉴 4.2 小时，落在 8–10 小时框架内。

### 18.2 设定补丁：助手是「实验台负责人」

“100% 后仍占用助手”在机制上成立，但需要一个说得通的理由：

> **助手不是研究机器，他是这个实验台的负责人。** 从入台到清场都归他管：做实验、写记录、清理台面。**台子不空，他不能走。**

这样三件事一次解释：

- **为什么占用**：他负责的不是“跑进度”，是这台子的全流程
- **为什么打断后还在**：你在做实验，他在旁边学
- **为什么清场才释放**：他要收尾

### 18.3 附带改名

实验“费用”在设定上改成 **实验耗材费**（试剂、容器、电）——这也解释了为什么助手是组织派的、不领工资，但你依然要花钱。

### 18.4 一次完整流程

```
新物种（未亲手做过）→ 放进实验室 → 助手不接手，只能玩家自己点
        → 玩家亲手做完这 5 条实验（助手在旁边观摩）
        → 该物种标记为「已亲自处理」
        → 之后再放入该物种的个体 → 助手开始自动研究（耗材费照扣）
        → 自动刷到 100%
        → 助手停下但仍占用
        → 玩家点「终末榨取」（按钮就在那只个体下面）
        → 个体死，产出样本（μ = 当前耐受 / 50）
        → 遗体占位 · 按现有规则花 6 金处理（不自动清场）
        → 台子空 → 助手释放，接下一个物种
```

**终末榨取的四条定案（2026-11-20）**：

| # | 项 | 决定 |
|---|---|---|
| 1 | 产物公式 | `μ = 耐受 / 50`（对齐克隆成本，一只换一只） |
| 2 | 榨完是否自动清场 | ❌ **不自动**：遗体照旧占位、花 6 金处理，然后助手才释放 |
| 3 | 按钮位置 | 就摆在那只个体下面 |
| 4 | 是否显示预计样本数 / 说明文字 | ❌ 都不显示（见 §14.7 文案规则） |

**分工**：手动 = 第一次探索（钥匙），自动 = 收尾与复制（引擎）。助手永远不能替你做“第一次”。

### 18.5 打断的定位（2026-11-20）

打断不是为了“救”，也不是为了效率——它没有任何数值优势。

> **打断 = 把它给我，我亲自来。**

- 玩家接管这个实验体，助手在旁边观摩（仍被占用）
- 可以随时把自动交还给助手
- 唯一的不同：**手动有反馈，自动只有日志**——你亲手做的每一次实验，都会看到它的反应

这条机制不为收益服务，它服务于角色：玩家的默认行为不是善。游戏不评价这件事，只是允许它发生。

### 18.6 日志与记录：自动研究怎么写

自动研究是**连续 tick**，没有离散的“第几次实验”，所以它没法像手动那样逐条落笔。

**沿用现有的日志结构**：按个体编号分组，组内按天。助手相关的记录用三条固定文案：

| 事件 | 文案 |
|---|---|
| 助手接手 | **「安排助手对其进行实验」** |
| 玩家打断、接管 | **「你决定亲自动手」** |
| 个体死亡 | 沿用 **「实验结束后对象死亡」** |

样例：

```
#0042  烈雀  Lv.58
  D12   安排助手对其进行实验
  D14   你决定亲自动手
  D14   用钳子从活体上硬扯下一块皮肉，伤口不缝合，观察它疼到抽搐。
                                                    [实验结束后对象死亡]

#0051  烈雀  Lv.55
  D15   安排助手对其进行实验
  D17   实验结束后对象死亡
```

- 组头**去掉「N 次」**，只留 编号 / 物种 / 等级
- 助手阶段不逐条记录，只有「接手 →（可选）打断 → 死亡」三类节点
- 助手阶段的死亡不配动作文案，只有那一行标记
- **研究到 100% 不额外记日志**：维持现有“研究满后不再写日志”的规则，完成与否由图鉴格子体现
- 手动做的实验仍逐条落在它自己那一组里

#### 图鉴里只给总数，不拆账

图鉴条目**不显示**「亲手几条 / 助手几只」这种拆分，沿用现有的两项总计：

- **损耗 N**（被研究消耗掉的个体总数，助手用掉的也算在内）
- **研究成本**（耗材 + 遗体处理）

数据层可以分开记录（`assisted` / `assistantLost`），但**界面不展示**——按 §14 的原则，它不改变玩家此刻的任何决定。

### 18.7 节奏定案（✅ 2026-11-20，按建议直接定，后续按体验调）

| 项 | 决定 | 理由 |
|---|---|---|
| **助手解锁** | **职级 3 · 高级研究员** | 实验室在职级 2 开；先让玩家手动做几个物种，等“手动开始变重”的时候助手正好到 |
| **第 2 个助手** | **职级 4 · 首席研究员** | 与“升职 → 管更多事”的设定同构 |
| **第 3 个助手** | **职级 5 · 干部** | 同上，封顶 |
| **打断后能否做“非首次”实验** | **可以** | 打断就是接管，玩家想做什么做什么 |
| 自动研究的其它限制 | 无（只有“未做实验压 2%”这一条） | — |

**为什么助手数量不必急着给满**：助手只是“后台那一路”，玩家自己的 2–4 台实验台始终在跑。助手多一个，等于少点很多次；但即使只有 1 个，游戏也能玩——只是慢。所以数量按职级给，是节奏调节，不是硬需求。

## 20. 蛋组错误的后代（畸形体）· 2026-11-24

> 状态：**视觉 ✅ 已定，规则数值待确认**，未改动任何代码。

### 20.1 起因

现行规则是：**异性 + 蛋组不匹配 → 争斗 → 死一只 + 永久锁对**。三个问题：

| 问题 | 说明 |
|---|---|
| 不合直觉 | 不同物种的异性不会互相残杀，它们只是配不上 |
| 试错代价是命 | 一次失败 = 死一只 + 锁一对 |
| 失败不产生知识 | 只记住"这对不行"，学不到任何可复用的东西 |

数据先摆出来：**144 个可繁育物种、15 个蛋组**，无序对 10296 组里只有 1571 组能配——**随机挑一对只有 15.3% 的成功率**。也就是说盲猜 6 次才对 1 次，而每次错的代价是一条命。

### 20.2 曾考虑的「宝可梦无限融合」——否决

规则层面完全可落地（头部 2/3 决定 HP/特攻/特防，身体 2/3 决定物攻/物防/速度；属性取头部第一 + 身体第二；特性各取其一），**卡在立绘数据上**：

| 事实 | 结论 |
|---|---|
| 第一世代融合全量 = 151² = **22,801 张**，约 500–600 MB | 静态站放不下 |
| `Aegide/custom-fusion-sprites` **已被 GitHub 以 ToS 关闭** | 公开素材源不可依赖 |
| 官方整包 **2.57–3 GB**，没有按需取单张的接口 | 无法懒加载 |
| InfiniDex 有结构化 API，但是**自托管 Docker**（FastAPI + PostgreSQL） | 不是公共服务 |
| 各类计算器站能看到图 | 无稳定单张 URL 规则，且是二创资产 |

> 顺带确认：**GitHub Pages 是可以请求外部资源的**（本项目 `data.mjs` 的 `remoteSprite()` 就在缺图时回退到 jsDelivr）。障碍不在技术，在于没有任何一个可依赖、授权干净的图源——主仓库已经因为 ToS 被关掉过一次。

**决定：放弃真融合图，用现有 151 张立绘程序化生成"畸形"。**

### 20.3 最终形态 ✅（涡流 + 轻度病变，单张立绘）

```css
filter: url(#warp-N) hue-rotate(140deg) saturate(.72) contrast(1.2);
```

```svg
<filter id="warp-N" x="-35%" y="-35%" width="170%" height="170%">
  <feTurbulence type="fractalNoise" baseFrequency="0.03 0.06"
                numOctaves="3" seed="N" result="n"/>
  <feDisplacementMap in="SourceGraphic" in2="n" scale="12"
                     xChannelSelector="R" yChannelSelector="G"/>
</filter>
```

```css
/* 尺寸一致：滤镜永远按 96px 算，再整体缩放 */
img.head{
  width: 96px; height: 96px;
  transform: scale(var(--k));      /* --k = 显示尺寸 / 96 */
  transform-origin: 0 0;
}
```

- **`N = hash(母方 dexId, 父方 dexId) % 997`**
- 同一对父母 → 永远同一副样子；**换父方 → 扭曲形态不同**
- 所以虽然外观只画母方，**父方仍然参与这张脸**

参数含义：`saturate(.72)` 是"颜色偏了但没坏死"（纯「腐」是 .18，原图是 1.0）；`scale=12` 是 12px 位移；`baseFrequency 0.03 0.06` 控制扭曲块的大小。

| **母方耐受** | **−44 / 次** | 正常配对是 40，只贵 10% |
| **父方耐受** | **−12 / 次** | 正常配对是 0，这是新增的 |
| **父方归零** | **死亡**（与母方同规则） | |
| 存活 | → 畸形体 | |
| 体质 | **0.5**（触底） | 耐受上限只有一半 |
| 繁育 | **不育** | 血统到此为止 |
| 图鉴 | **无条目**、不占图鉴 | |
| 研究 | **不推进任何物种研究** | 放进实验室也不给进度 |
| 样本 | **终末榨取 1 份** | 不能给 2 份，否则变成刷材料 |

### 20.4.1 代价核算（以「正常一只后代 = 40 耐受」为基准）

| 维度 | 一只畸形体 | 倍数 |
|---|---|---|
| 母方耐受 | 63（44 × 1.43） | 1.6× |
| 父方耐受 | 17（12 × 1.43） | — |
| **合计耐受** | **80** | **2.0×** |
| 游戏内时间 | 3.6 天（≈43 秒真实） | 5.7× |
| 金币 | 0 | — |
| **产出价值** | **0.15** | **13.3×（按价值口径）** |

**父母能撑多久**：

| 母方等级 | 耐受上限 | 能出几只畸形体 |
|---|---|---|
| Lv.1 | 100 | 1.6 |
| Lv.30 | 158 | 2.5 |
| Lv.60 | 218 | 3.5 |

父方 12/次：Lv.1（125）可参与 10 次、Lv.60（273）可参与 22 次——**父方不是瓶颈，母方才是消耗品**。

**为什么耐受只贵 10%**：惩罚的主体是"后代是废物"（价值 0.15），耐受再加码就是双重惩罚。按价值口径，即使耐受压到最低，跨蛋组仍然是 13 倍亏损——它本来就该是"没有别的路时才走"。

### 20.4.2 两个已知风险（实施时要注意）

1. **父方死亡不可见**：耐受度只有在实验室里才显示，培育栏/围栏看不到。父方因跨蛋组配对耗尽而死，玩家事先没有任何提示，属于"暗坑"。**实施时先观察**；若玩家反馈突兀，再考虑在配对选择器给"扛不住这一胎"的个体标一个「虚弱」——那是决策相关信息，不违反 §14。
2. **30% 死胎率很便宜**（尝试成本只有 1.43 次），跨蛋组从"赌命"变成"可行"。这条成立的前提是**所有变现口都堵住**：禁止交单（已定）、卖价 15–20%、样本只有 1 份。任何一项放开，它都会变成稳定刷法。

### 20.5 蛋组知识的获得 ✅（2026-11-24）

**结论：蛋组名只由研究 100% 揭示；能不能配，看后代的形态。**

| 玩家想知道的 | 获得方式 |
|---|---|
| 这两个能不能配 | **看后代**：正常后代 = 蛋组匹配；畸形体 = 蛋组不匹配 |
| 这个物种属于哪些蛋组 | **研究进度 100%** 时揭示（之后永久可见） |
| 该拿谁去配 | 研究 100% 之后知道，或者试出来 |

配套改动：

- **取消"繁育成功揭示蛋组"**（原 `revealEggGroups` 的"成功一次揭示交集"）。蛋组不再从繁育里泄漏。
- 没研究完的物种仍是 `？？？`。
- 选择器里的"同蛋组绿框"只在**双方蛋组都已知**时出现——它不是主要判断依据，只是确认。
- 不再需要"失败也产出负信息"那套机制：**结果就是信息**。

### 20.6 死胎的信息问题 ✅（2026-11-24 选定 C）

跨蛋组的 30% 死胎，和正常配对因体质差产生的死胎（0–6%），**在结果上无法区分**——两者都只显示"这一胎没有成型"。

于是玩家看到一次死胎时，分不清是：

- 「配上了，但胎停」→ 说明蛋组是匹配的
- 「根本没配上，只是没到畸形体那一步」→ 说明蛋组不匹配

**选定 C：接受这个模糊。**

- 30% 与 0–6% 差着一个量级，玩家多试几次就能靠概率推断
- **不增加文案、不增加规则**——按 §14.7，不为"解释"多写一句
- 代价：新玩家第一次遇到死胎时无法判断。可以接受，因为他的下一步（再试一次）不受影响

曾考虑但否决的两个做法：

| | 做法 | 否决理由 |
|---|---|---|
| A | 两种死胎用不同文案 | 多一条只为解释而存在的文案，违反 §14.7 |
| B | 不匹配时不走"死胎"，栏位空转 | 最模糊，且不如 C 诚实（至少 C 给了概率） |

### 20.7 被否决的候选（记录理由，避免重走）

曾把"错误"拆成四种（腐 / 畸 / 错 / 裂）并考虑随机分配，后来试了更多做法，全部否决：

| 候选 | 做法 | 否决理由 |
|---|---|---|
| 裂（条带） | A 完整 + B 的细条带裁进 A 的轮廓 | 需要"用图片当 alpha 蒙版"，实现与调试成本高，且父母长得像时完全看不出 |
| 切片错位 | 同图切三条横移 | 太像"特效"，不像"长坏了" |
| 横撕 | SVG 逐行横向位移 | 与涡流重复，且组合后互相削弱 |
| 负片块 | 矩形区域反相 | 矩形读起来是"贴纸"，不是身体的一部分 |
| 肿块 | 圆形区域放大 | 只有一个位置，辨识度低 |
| 拖影 | 两层错位半透明 | 像"没对齐"，不像"活物" |
| 补丁（矩形） | 父方一块矩形贴到母方身上 | 同上，太规整 |
| 差值 / 蒙版反相 | 按父方轮廓做负片 | 想法对（形状来自父方），但颜色被父方污染，且依赖蒙版 |

**最终只用一种效果**：涡流本身就同时表达了"形状不对"和"它不该长这样"，比四种更好辨认；四种方案会让玩家花成本在"分辨类型"上，而分辨本身不改变任何决定（§14 的原则）。

### 20.8 技术教训（踩过的坑）

1. **SVG 位移滤镜的坐标是像素**：同一张图在不同尺寸下扭曲强度不同 → 固定 96px 渲染 + `transform: scale()`。
2. **不要用 `primitiveUnits="objectBoundingBox"`**：部分浏览器不把 `scale` 解释成百分比，`0.17` 变成 0.17px，效果直接消失。
3. **图片蒙版别通过 CSS 变量传**：`--m: url(...)` + `mask-image: var(--m)` 会拿不到图，整层被裁空 → 直接写内联 `style`。
4. **蒙版会建立合成上下文**：嵌套蒙版里的 `mix-blend-mode` 找不到可混合的背景，会退化成原图 → 改用 `filter: invert()`。
5. **`filter` 可以混写**：`url(#滤镜) hue-rotate(...) saturate(...)` 是合法的，先跑 SVG 位移再跑色彩函数，顺序反过来结果不同。
6. **诊断必须用高对比度配对**：烈雀 × 波波两只棕色小鸟，替换 20% 像素肉眼完全看不出——浪费了三轮调试。

### 20.9 围栏的「畸体」段 ✅（2026-11-24）

畸形体不进普通围栏列表，而是和「培育相关」「其它」**并列的第三段**。

| 项 | 规定 |
|---|---|
| 位置 | 与「培育相关」「其它」**同层级**，作为开关上的**第三段**（不是底部独立块） |
| 开关 | 从两段变三段：培育相关 / 其它 / **畸体** |
| 显示条件 | **只在存在畸形体时出现这一段**（按钮与内容都出现；没有畸体时开关仍是两段） |
| 普通列表 | 畸形体**不出现在**「其它」里，不重复展示 |
| 段头 | 「畸体 N 只」 |
| 段内可做 | 查看详情、出售、送进实验室 |
| 段内不可做 | 交单（§20.4）、放进培育栏（不育） |
| 围栏霸凌 | **不参与**——它们已经被单独归到这一段，不与同物种成群 |
| 遗体栏 | 不变，仍是底部独立块（它不是一个"分类"，是一堆待处理的东西） |

**为什么单独一段而不是塞进「其它」**：畸形体在规则上是"另一类东西"（无图鉴、不育、只能贱卖或做样本）。混在普通列表里会污染"我在养的那些"这条视觉主线；分开之后，玩家看到「其它」就是"还能用的"，看到「畸体」就是"该处理的"。

**为什么不做成底部独立块**：底部那块现在是「遗体」——它读起来是"垃圾待处理"。畸形体虽然也废，但**它是活的、能卖、能送实验室**，和遗体不是一回事。放进开关的同一层级，才表达"这是围栏的第三类东西"。
