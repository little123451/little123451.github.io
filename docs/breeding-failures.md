# 配对（繁育）失败：现状、问题与调整方案

> 状态：**分析稿**，未改动任何代码
> 基线：`master@9f2d854` + 已实施的 A1（升级价格表修复）
> 相关文档：[docs/breeding-plan.md](breeding-plan.md)（总方案，本文是其中"失败路径"的展开）

---

## 0. 结论先行

配对失败一共 **9 种判定 + 3 种结算卡点**，后果分成三类：

| 后果 | 有几种 | 具体 |
|---|---|---|
| **死一只（可能连锁死两只）** | 4 种 | 同性、双百变怪、未发现蛋组、异性蛋组不匹配 |
| **不产蛋、静默或纯空转** | 3 种 | 不孕不育、已锁定组合复用、**无性别（与任何配对都不争斗）** |
| **卡住不动、无任何提示** | 2 种 | 蛋位满、承担方力竭（这个会死人） |

**真正值得调整的只有 5 处**，其余是设计本意（"博士只能靠试"）。按性价比排序：

1. **双百变怪相遇会死人** —— 最反直觉，玩家囤百变怪是正常操作
2. **蛋位满静默卡 100%** —— 最常见，玩家以为是 bug
3. **锁定/不孕组合的繁育条空转 2.5 天 × 无限次** —— 纯浪费时间 + 刷日志
4. **未发现蛋组物种可以放进栏位** —— 尼多娜陷阱（详见 F5），会打死对方
5. **力竭/连锁死亡事件没有栏位反馈** —— 玩家看不到"刚才死了谁"

## 2. 逐项问题

### F1 / F4 / F5 —— 三种"会死人"的失败

共同机制：`compatibility` 返回 `ok:false` 且没有 `sterile`/`quiet`/`code:'egg-group'`，于是落入 `resolvePen` 的争斗分支（[js/logic.mjs:1338-1357](../js/logic.mjs#L1338-L1357)）：`weakerOf` 判定弱者 → 留下遗体 → 强者 −28 → 若 ≤0 再死。

**F4 双百变怪是最该先修的**：

- 百变怪在蛋贩子池里（`weightedSpecies` 只排除传说/幻兽/`no-eggs`，[js/logic.mjs:622-643](../js/logic.mjs#L622-L643)），单个货位的出现率约 **1.69%**（63 种候选池），蛋价 687~831。
- 百变怪的价值恰恰是"能配任何物种"，玩家自然会囤两三只 → 放进同一栏 → **直接死一只**。
- 而且从设定上，两只百变怪"打起来"毫无道理——它们连性别都没有。

**F3 无性别**：151 只里 13 只无性别，其中 5 只买得到（81 小磁怪、100 霹雳电球、120 海星星、132 百变怪、137 多边兽，合计约占货架单个货位的 **7.8%**）。原实现里"买两只小磁怪想凑一对"会直接死一只且没有任何解释——现已改为**完全静默**：无性别个体与任何配对都不争斗，栏位里会写明「没有性别，配不了」。

**F5 未发现蛋组有一个隐藏陷阱**：

```
29 尼多兰 (monster/ground) ──Lv.16 自动进化──▶ 30 尼多娜 (no-eggs) ──月之石──▶ 31 尼多后 (no-eggs)
32 尼多朗 (monster/ground) ──Lv.16 自动进化──▶ 33 尼多力诺 (monster/ground) ──月之石──▶ 34 尼多王 (monster/ground)
```

雌性线**进化一次就永久失去繁育能力**，而且放进栏位会打死配偶；雄性线完全不受影响。玩家把尼多兰练到 16 级（完全正常的养成操作）就会踩中，且没有任何提示。

**这四类的共同问题**：

| 问题 | 说明 |
|---|---|
| 代价与操作不匹配 | 一次"放错" = 损失一只个体，而放入操作没有任何确认 |
| 文案不可区分 | 四类失败都产出 `A 与 B 没能配成，争斗中 A 伤重不治`（L1347），玩家学不到原因 |
| `assignPen` 完全不拦 | 只拦实验室、已在栏位、已锁定组合（L867-889），对上面四类一律放行 |
| 事件无栏位反馈 | 连锁死亡/力竭的事件不带 `pen` 字段（L1316、L1353），UI 拿不到栏位索引就不播动画（[js/ui.mjs:173-174](../js/ui.mjs#L173-L174)） |

### F2 —— 异性蛋组不匹配（永久锁定）

现状：死弱者 + 写 `failedPairs`（`"16-74"` 这种排序 key），此后：

- `assignPen` 拒绝再把这两个物种放进同一栏（L876-878）；
- UI 选择器把该物种置灰，title 说「曾与X配对失败，不可用」（[js/ui.mjs:1481-1483](../js/ui.mjs#L1481-L1483)）；
- 如果这一对**已经在栏里**，`resolvePen` 每 2.5 天刷一条警告（L1292-1301），条永远走 2.5 天就清零，直到玩家手动拆对。

问题：

| # | 问题 | 影响 |
|---|---|---|
| a | **永久且无解除入口** | 玩家想"再试一次"没有任何途径；存档里的 `failedPairs` 只增不减 |
| b | **不自动拆对** | 已经锁定的对留在栏里，每 2.5 天刷一条 warn（≈ 每次一轮 30 秒），日志 40 条上限很快被灌满 |
| c | **物种级 vs 个体级** | 锁的是物种组合，任何一个该物种都不能再配——对蛋组这种物种级属性是对的，但玩家读起来像是"这两只记仇了" |
| d | **与知识解锁不联动** | 该物种研究到 100% 后你已经知道全部蛋组，锁定却没有因此解除 |
| e | **选择器只说"不可用"** | 不告诉玩家"为什么"以及"有没有办法解" |

### F6 —— 不孕 / 不育

现状：`compatibility` 返回 `sterile:true` → `resolvePen` 单独分支（L1331-1336）：警告、清条、不争斗、不扣耐受。

问题：

- **空转**：条会完整走满 2.5 天（约 30 秒）才提示，之后每轮重复。
- **重复警告**：与 F9 一样，同一对留在栏里就无限刷。
- **会掩盖其它原因**：`sterile` 判定（L484）排在性别（L486）与蛋组（L488）之前，所以"不孕的雄性 + 另一只雄性"只会报「不孕」，不会报「需要一雄一雌」。
- **不拦放入**：卡片上明明有「不孕」徽章，但 `assignPen` 照样收。

### F7 —— 承担方力竭

现状：`bearer.tolerance − 32 ≤ 0` → `releaseMon(bearer, 'exhausted')`，不产蛋，事件 `X 在繁育中耗尽了耐受度，力竭而死`（L1310-1318）。

问题：

- **培育页看不到耐受度**（设计如此：只有进实验室才显示），玩家无法预判配偶快死了。
- **事件没有 `pen`** → 栏位不播动画、不弹红条，只有一条 toast。
- **不留遗体**：实验室死留 `corpse`、围栏霸凌死留 `idleCorpses`，培育栏死直接消失（L1021-1034）。三处不一致。
- **文案不完整**：只说"力竭而死"，没说"这次没产蛋"。

### F8 —— 蛋位满

现状：兼容且蛋位满时 `pen.breed = 2.5` 并 return（L1305-1308），不扣耐受、不受伤。

问题：UI 只把条画到 100%（[js/ui.mjs:599-607](../js/ui.mjs#L599-L607)），`#pen-i-warn` 只在绝育/锁定时显示，`#egg-hint` 只有 `N/M 枚蛋`。玩家看到的现象是**繁育条永远卡在 100%**，没有任何解释——这是最容易被当成 bug 的一个。

### F9 —— 已锁定组合复用

现状：警告 + 清条 + 不拆对（L1292-1301）。

问题：每 2.5 天一条 `A 与 B 曾配对失败，不能继续同栏繁育`。如果玩家没注意，这条会一直刷到拆对为止，把日志和 toast 都占住。

### F10 —— 争斗连锁死亡

现状：弱者死 → 强者 −28 → 若 ≤0 再 `releaseMon`（L1348-1357）。

问题：一次配对损失两只，且是两条独立 warn；第二条（`B 也在争斗中耗尽了耐受度`）同样没有 `pen`。

### F11 —— 反馈通道本身会丢消息

```js
// ui.mjs:169-172
if ((e.type === 'evolve' || e.type === 'egg' || e.type === 'warn' || e.type === 'research') && important < 2) {
  toast(e.msg, e.type === 'warn' ? 'bad' : 'good');
  important++;
}
```

- **每批事件最多 2 条 toast**：一次 tick 里若同时发生「配种成功 + 蛋孵化 + 争斗死亡」，只有前两条能看到。
- **日志只在内存**（`logs` 数组，上限 40，[js/ui.mjs:53](../js/ui.mjs#L53)、154-157），刷新页面就没了；`state.log` 是只写不读的死数据。

## 3. 调整方案

按主题分组，每项给「选项 / 推荐 / 代价」。

### T1 — 阻止"必然白死"的放入

| 选项 | 做法 | 推荐度 |
|---|---|---|
| **T1-a 双百变怪拒绝放入** | `assignPen` 里对 `isDitto(a) && isDitto(b)` 直接拒绝，文案「两只百变怪凑不出什么来」 | ★★★ 强烈推荐 |
| **T1-b 未发现蛋组拒绝放入** | `assignPen` 里对 `no-eggs` 直接拒绝，文案「它属于未发现蛋组，配不了」；顺带救掉尼多娜陷阱 | ★★★ 强烈推荐 |
| T1-c 同性加风险提示 | 放入时不拦，栏位上显示一句模糊提示（如「这两只看起来不太对劲」），不揭示具体原因 | ★★ 可做，但会削弱"只能靠试" |
| T1-d 保留现状 | 只改文案，不改行为 | ★ 会让玩家继续白死 |

> 为什么只拦这两种：**双百变怪**和 **no-eggs** 在设定上根本不是"会打架的生物"，拦掉不伤叙事；而同性/蛋组不匹配是真正的"配对失败"，留着试错符合设计。
> **无性别**属于第三类：它既不是"该拦"也不是"该打"，最终按"静默配不上"处理（见 §7 实施记录 D3）。

### T2 — 争斗后果（大决策）

| 选项 | 规则 | 优点 | 代价 |
|---|---|---|---|
| T2-a 保持必死 | 现状 | 残酷感强，与实验室的死亡呼应 | 一次放错 = 掉一只，玩家容易骂娘 |
| T2-b 不死，双方重伤 | 双方各 −28~40 耐受，强制该栏位冷却 N 天 | 保住个体，惩罚仍在 | 失去"失败会死人"的紧张感；要改 README 与 4 条测试 |
| **T2-c 弱者重伤但活着，连锁才死** | 弱者 −40，若因此 ≤0 才死；强者 −28 | 保留死亡可能，但只有"连续失败/低等级"才会发生 | 中等改动，测试需重写争斗断言 |

> 若不动 T2，至少要把 **F1/F4/F5 的死法差异化**：现在是同一句文案，玩家分不清"这是随机的还是我配错了"。

### T3 — 锁定机制

| 选项 | 做法 | 推荐度 |
|---|---|---|
| **T3-a 研究 100% 自动解除** | 该物种研究完成后，`failedPairs` 里相关条目自动清除（你已知蛋组，不再需要"试错记忆"） | ★★★ 优雅，与知识系统联动 |
| **T3-b 花钱解除** | 如 500 资金「重新调教」清掉该组合 | ★★★ 给玩家出口 |
| T3-c 随时间遗忘 | 30 天后自动清除 | ★★ 隐性，玩家感知弱 |
| T3-d 保持永久 | 现状 | ★ 会积累成永久噪音 |
| **T3-e 已锁定的对自动拆对** | 结算时把弱者移回围栏（不受伤），并在栏位显示「已拆对」 | ★★★ 推荐与上面任意一项组合 |
| T3-f 同一对只警告一次 | 用 `warnedPairs` 去重，或直接把警告降级为栏位常驻提示 | ★★★ 推荐（无论锁不锁） |

### T4 — 状态与反馈

| 项 | 做法 | 推荐度 |
|---|---|---|
| **T4-a 蛋位满状态** | 条变橙 + 「孵化器已满，繁育暂停」+ 「去升级孵化器」按钮 | ★★★ |
| **T4-b 锁定 / 不孕 条置灰** | 不再空转 2.5 天，直接 0% 灰色 + 一句原因 + 「移出栏位」 | ★★★ |
| **T4-c 事件补 `pen`** | 力竭、连锁死亡事件加栏位索引，UI 能播动画/弹红条 | ★★★ |
| **T4-d warn 优先** | toast 分配改成"先给 warn，再给 egg/evolve"，或失败用栏位内红条而非 toast | ★★ |
| T4-e 失败文案分级 | 至少三类：「打起来了」「没怀上」「没配上（力竭）」；不揭示蛋组等隐藏信息 | ★★★ |
| T4-f 培育栏死亡留遗体 | 与实验室/围栏一致，需花 6 资金处理 | ★★ 可选，会加重惩罚 |

### T5 — 代码一致性

| 项 | 说明 |
|---|---|
| **T5-a `penOutcome` 单一真相源** | 把"条满后会发生什么"收进 `logic`（总方案 B 包），UI 不再自己判 `compatibility`。这是 T4-b 的前置 |
| T5-b `compatibility` 形参 | `state` 从未使用（L471-491），`failedPairs` 判断散落三处；要么去掉形参，要么把锁定判定收进去 |
| T5-c `weakerOf` tie-break | 用 uid 字符串比较（`'u10' < 'u9'`，L565-566），同级同种族值时"谁死"取决于编号；建议改数值比较 |
| T5-d 事件统一形状 | 所有失败事件统一带 `{ pen, kind, msg }` |

## 4. 三档推荐组合

### 保守版（只修"必然白死"和"静默卡死"）— 约半天

- T1-a 双百变怪拒绝放入
- T1-b no-eggs 拒绝放入
- T4-a 蛋位满状态提示
- T4-b 锁定/不孕 条置灰 + 一键拆对
- T4-c 事件补 `pen`
- T3-f 同一对只警告一次

**不动数值、不动死亡规则、不改 README 的玩法说明**，纯修 bug 与表达。

### 中等版（+ 锁定出口 + 文案分级）— 约 1 天

保守版 + T3-a 研究完成自动解除 + T3-b 花钱解除 + T3-e 自动拆对 + T4-e 文案分级 + T5-a `penOutcome`。

### 激进版（+ 争斗不再必死）— 约 1.5 天

中等版 + T2-c（弱者重伤，连续失败才死）。**需要改 README §7 与 test-logic 的 4 条争斗断言**。
