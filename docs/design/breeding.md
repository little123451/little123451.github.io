## 13. 繁育的设定定位（2026-11-20，✅ 已认可）

> **培育栏是产线也是样本库：母体是耗材，蛋是货，也是实验材料；每只子代都要决定归组织还是归你。**

### 13.1 为什么是这个定位

- **抢来的货不可持续**：图鉴 151 个、订单每天要人，靠蛋贩子和抢，供给是断的。繁殖是唯一"自己造"的环节——组织眼里它是**资产自我复制**，不是照顾宝可梦。
- **研究需要样本量**：抢来的每一只都是孤本，做不了对照、复不了现。**繁育是博士唯一能造出"第二只同种"的办法。**
- **代价必须有**：母体耐受 −32、Lv.1 只能产 3 只、力竭即死——这三条已在代码里，正好构成"工业"的残酷感。

### 13.2 三个视角 → 三个机制落点

| 视角 | 看到的繁育 | 评价标准 | 机制落点 |
|---|---|---|---|
| **组织** | 资产自我复制 | 数量、等级、物种对口 | 批量订单（后勤部一次要 5 只一般系） |
| **你** | 样本供应 | 同种几只、能不能对比、体格 | 研究部订单（要 3 只同种做对照） |
| **代价** | 母体是耗材 | 还能产几只 | 母体耐受在栏位可见、力竭死 |

两个订单形态都复用现有订单系统（多一个 `qty` 与一种需求类型），不新开。

### 13.3 核心动作是"分岔"，不是"配种"

| 去处 | 换来什么 | 失去什么 |
|---|---|---|
| 交组织（订单） | 资金 + 声望 | 这只再也见不到 |
| 送实验室 | 研究进度（第 N 个样本） | 大概率死在台上 |
| 留下当种 | 下一轮的亲本 | 占栏位、耗空间 |
| 卖黑市 | 现金 | 价格最低、没有声望 |

这四个去处**界面里都已经有了**。缺的不是按钮，是"个体之间有差异"和"每个去处读不同的维度"。近亲把这个决定拉长：留种最快的是自交，但后代越来越脆；要长期就得买外血。

### 13.4 这个定位排除什么

- ❌ 不做亲密度 / 羁绊（README 已声明）——培育栏里没有温情，只有耐受度和产线。
- ❌ 不做"保育"叙事——你是被"请"进来的。
- ❌ 不做随机出稀有——稀有感来自体格与血统，不是抽卡。

### 13.5 落地顺序（建议）

1. **表达层**：让"产线/样本库"被看见（母体产能、体格、血统）
2. **机制层**：近亲 K2、配种意图
3. **出口层**：各去处读不同维度（订单读等级/物种、黑市读体格……）

### 13.6 体格（🕒 2026-11-20 决定：先不做）

讨论过甲、乙两案（星级直接由 IV 算 / 由已披露的能力值推导），**最终决定先不做体格机制**。

替代方案：**研究 100% 后，个体详情直接给出六项 IV 的具体数值。**

| | 保留 | 放弃 |
|---|---|---|
| 知识阶梯 | 研究 → 认识个体 | 卡片/列表层面的星级快速比较 |
| 认知节奏 | 未研究时仍是 `？？？` | 部分披露时的中间反馈 |

**代价**：挑亲本只能打开详情看数值；只有研究透的物种才谈得上"聪明地育"。这与"繁育是样本库、只对少数物种建品系"的定位是一致的。

**数据没丢**：`mon.ivs` 完整保留，以后想再起体格不需要改结构。

### 13.7 近亲与体质（✅ 2026-11-20 已定）

#### 先立住前提：近亲是有收益的

回交能把优等基因快速固定下来——这是现实育种的标准手段，不是偷懒。单项 IV 举例：

| 配对 | 子代均值 |
|---|---|
| 优等（28）× 它的子代（20）＝回交 | **24**（区间 19–29） |
| 优等（28）× 市场外血（15） | 21.5（区间 16.5–26.5） |

所以近亲不是纯惩罚：**提纯快，但体质退化**。这才构成取舍。

#### 决定

| # | 决定 | 内容 |
|---|---|---|
| 13-1 | ✅ **代价落在“体质”**（2026-11-24 改为分级） | 非近亲 = `双亲均值 + 0.2`，封顶 1；近亲 = `min(双亲) × 乘数`，下限 **0.5** |
| 13-1a | ✅ **乘数按关系远近分级** | 直系 **0.70**（任意代）／同胞 **0.78**／叔侄·表亲 **0.88**／二代表亲 **0.95**／三代以外 **不惩罚** |
| 13-1b | ✅ **判定：直系优先，旁系看深度** | **直系**：一方在另一方的祖先表里，**不看深度**（隔多少代都一样狠）。**旁系**：取所有共同祖先里 `max(双方深度)` 的最小值 |
| 13-1c | ✅ **标记与惩罚同步** | 乘数 **≤ 0.95 才显示「近亲」**；三代以外不惩罚、也不显示。标记仍只有一个词，不做分级（§14.6 不变） |
| 13-2 | ✅ **系数乘在耐受上限上** | 不新增 UI，体现为已有的耐受灰度变短 |
| 13-3 | ✅ **死胎与系数绑定** | 系数 ≥0.85 时 **0%**；0.72 → 2%；0.61 → 4%；0.50 → 6%。死胎照常消耗母体 **40** 耐受 |
| 13-4 | ✅ **开局 3 只** | 波波♂ + 烈雀♀ + 烈雀♀（后两只无亲缘）。**两只雌性必须是同一物种**，否则断线风险不会下降（见下） |
| 13-5 | 🕒 **断代保护暂缓** | “无任何可繁育个体时市场必出百变怪”——设计认可，但实现复杂度与触发频率不划算，记为以后 |

#### 分级乘数表（2026-11-24）

```
直系 0.70  ──  同胞 0.78  ──  叔侄·表亲 0.88  ──  二代表亲 0.95  ──  三代以外 无惩罚
   ↑ 两代就废                    ↑ 六代                 ↑ 十三代
```

| 关系 | 深度 | 乘数 | 显示「近亲」 |
|---|---|---|---|
| 直系（亲子 / 祖孙 / 曾祖孙…） | 任意 | 0.70 | ✅ |
| 全同胞 / 半同胞 | 1 | 0.78 | ✅ |
| 叔侄 / 表亲 | 2 | 0.88 | ✅ |
| 二代表亲 | 3 | 0.95 | ✅（阈值上） |
| 三代以外 | ≥4 | 不惩罚 | ❌ |

**为什么直系不看深度**：隔两代、五代的直系亲属，在直觉和遗传上仍然是同一回事——它是“血统没有分叉”，不该因为代数变远而变轻。旁系不同，交叉得越远越接近“没有关系”。

#### 系数对照（已计入“栏位内升级回补耐受”与“产下最后一胎再死”）

| 系数 | Lv.1 雌性上限 | 实际能产几胎 | 死胎率 |
|---|---|---|---|
| 1.00（外血） | 100 | **3** | 0% |
| 0.85 | 85 | 3 | 0% |
| 0.78 | 78 | 2 | 2% |
| 0.72 | 72 | 2 | 2% |
| 0.61 | 61 | 2 | 4% |
| 0.50（触底） | 50 | 2 | 6% |

#### 连续这样配的衰减速度

| 配对方式 | 乘数 | 第1代 | 第2代 | 第3代 | 第4代 | 第5代 | 触底 |
|---|---|---|---|---|---|---|---|
| **一直亲子回交** | 0.70 | 0.70 | **0.49→0.50** | 0.50 | 0.50 | 0.50 | **2 代** |
| 一直全同胞 | 0.78 | 0.78 | 0.61 | 0.50 | 0.50 | 0.50 | 3 代 |
| 一直叔侄 / 表亲 | 0.88 | 0.88 | 0.77 | 0.68 | 0.60 | 0.53 | 6 代 |
| 一直二代表亲 | 0.95 | 0.95 | 0.90 | 0.86 | 0.81 | 0.77 | 13 代 |

#### 数据结构的连带改动

现在的 `ancestors` 是**平铺的 uid 数组**，没有深度，无法区分“父亲”和“曾祖父”。要支持分级判定，得改成记录最近代数：

```
ancestors: { [uid]: depth }     // 该祖先到我的最近代数
```

| 判定 | 算法 |
|---|---|
| 直系 | 对方的 uid 出现在我的 depth map 里（任意深度） |
| 同胞 | 双方 depth=1 的祖先有交集（共享父母） |
| 旁系深度 | 共同祖先里 `max(我的depth, 他的depth)` 的最小值 |

涉及 `lineageOf`、`isKin`、`createEgg`、`createMon` 与存档结构。**没有向后兼容**，旧存档直接作废。

⚠ 注意：**“能产几胎”不是常数**。培育栏同时给被动经验（26/秒），母体在产仔过程中升级，而升级会把耐受上限的增量补回给她。所以先养到高等级再配，产量更高；等级越高，近亲惩罚的绝对影响越小。

#### 为什么不做这两种

- ❌ **不做耐受税**（K2 的 32→48）：近亲在现状里是默认路径（同种外血几乎买不到），加税等于全体产能 −25%，玩家没有替代方案，是罚款不是选择。
- ❌ **不做随机畸形率**：与“可复现的规律”的基调不符。死胎是体质差的自然表现，玩家能算出来，这才写进笔记。

#### 启动容错

原担心：开局只有一个母体，3 胎全雄（12.5%）就断线。
解法不是“给个体翻倍体质”（耐受是全局资源，翻倍会连带影响实验室，且设定上说不通），而是**多给一只同物种的雌性**：

- 两只烈雀♀ → 该物种 6 胎，全雄概率从 12.5% 降到 **1.56%**
- 注意：**两只雌性必须同物种**。若一只烈雀♀、一只超音蝠♀，则每条线仍只有 3 胎，断线风险不变，只是多了个物种。
- 保留波波♂ 作父本，还能顺带教会玩家“子代随母方”（波波 × 烈雀 → 烈雀）
- 设定上说得通：**基地配发的第一批样本是三只**

### 13.9 同性配对的设计意图（2026-11-20）

> ⚠ **本节已被 2026-11-24 的决定取代。**原方案是“同性配对 = 玩家主动的恶，游戏要给回应（争斗死一只）”。新决定更干脆：**两只同性的个体不允许放进同一个培育栏**，入口就拦住；`compatibility` 的 `same-sex` 分支、`fightToleranceLoss`、争斗文案与统计全部删除。下面的内容仅作为设计过程的记录保留。

> 繁育是一公一母的配对。玩家刻意放进两公或两母，说明他有额外的想法——这个行为被定义为**“主动的恶”**，游戏应当反馈它。

现状：同性配对与蛋组不匹配共用同一条结算路径（争斗 → 弱者死），只是原因文案不同。所以它读起来像系统判定，不像“它对你的回应”。

待展开的方向（未拍板）：

- 结果文案专属化：同性配对不该复用“争斗中伤重不治”。
- 明确“没有产出”：它不产生任何数据——这是研究员自己的评价标准，不是道德指责。
- 行为被记录：重复这样做会在研究笔记里留下痕迹。
- 数值是否仍为“死一只”，待定。

### 13.10 内部循环收口（2026-11-20）

按「放入 → 等待 → 结算 → 蛋 → 孵化 → 接班」走了一遍：

| # | 环节 | 决定 |
|---|---|---|
| 1 | 力竭结算 | ✅ **产下最后一胎再死**（不再"白等一轮然后死"） |
| 2 | 养成耦合 | ✅ **承认现状，暂不调整**：栏位内升级会回补耐受，母体越养越能生。这是巧合不是设计，但先按简单做法跑 |
| 3 | 孵化反馈 | ✅ 普通孵化只进日志；**只有异常才强调**（虚弱、不孕、闪光、首次孵出该物种），避免批量繁育被打断 |

其余环节的结论：

| 环节 | 结论 |
|---|---|
| 放入 | 保持“只能填空栏位”，不加栏位间移动 |
| 选择器 | 显示物种、性别、等级、性格、已知蛋组、近亲标记、不孕标记；**不显示“能不能配”**（博士只能靠试） |
| 蛋位满 | 栏位写明「孵化器已满」，别让条停着不说话 |
| 蛋卡 | 物种 + 剩余天数；父母/来源点开再看 |
| 接班 | **不需要谱系 UI**——玩家只要在选择器里看到「近亲」就够（§14.5） |

已知但暂不处理：

- 近亲惩罚被等级稀释（Lv.60 母体 ×0.5 仍有 109 耐受上限）。
- “先养到高等级再配”成为最优解——耦合的副作用，不是设计目标。

#### 收口备注

繁育的核心循环未变，本轮实质是加了**一层长期约束（近亲/体质）** + 五处修补。代价有了，但“为什么配这一对”的目标要等研究 100% 能看到 IV 之后才真正成立——繁育因此天然分两档：未研究（防近亲）／研究透（追数值）。

### 13.12 入口与蛋的处理（2026-11-24）

#### 同性配对：入口拦截

| 变更 | 内容 |
|---|---|
| 选择器 | **不做校验、不做置灰**：只把**同性**个体从列表里去掉。空栏位列出全部；已放入一方时，去掉与它同性的那些——**异性、无性别、百变怪照常列出** |
| `compatibility` | 删除 `same-sex` 分支 |
| 争斗机制 | **整体删除**：`fightToleranceLoss`、`stats.fights`、争斗文案、相关测试一并移除 |
| 百变怪例外 | 百变怪可与任意性别配，不受此规则限制 |
| §13.9 | 整节作废（原文保留作过程记录） |

**为什么是“不展示”而不是“置灰”**：置灰等于告诉玩家“这里本来有个选项，但你不能用”——那是在解释一个不存在的选择。不展示，玩家根本不会意识到有这回事，也就不需要任何说明（§14.7）。

**为什么不再给“回应”**：争斗原本是“玩家刻意把两只同性放一起”的反馈。现在入口就拦住，玩家根本没有机会表达这个意图——**没有输入，就不需要回应**。

⚠ 连带影响：争斗删除后，繁育里唯一“会死人”的路径只剩**力竭**；`weakerOf` 只剩围栏霸凌在用。

#### 蛋：不能丢、不能卖，只等孵化

| 项 | 结论 |
|---|---|
| 丢弃 / 出售 | **没有入口**，蛋只能孵 |
| 蛋位满 | 栏位显示「孵化器已满」，进度停在 2.5 天，**不惩罚** |
| UI | **待简化**：现在是 立绘 + 物种 + IV + 性格 + 进度条；计划只留 **物种 + 剩余天数**，父母/来源点开再看 |

**为什么不给“丢弃”**：蛋是繁育唯一的产出。可丢弃就等于可“重摇”——玩家会为了刷性格/IV 反复生、反复丢。**必须孵出来**（占一个围栏位置、要处理），才构成真实的产能压力。

### 13.13 近亲称呼（2026-11-24，`Accepted, not implemented`）

> 状态：已定、未实施（`docs/backlog.md` #3 / B3）。实施前界面仍是「近亲」徽标 + 详情页「近亲后代 · 第 N 代」。
> 决定：把二元徽标换成**亲属称呼**，只在配对选择器出现；**详情页的「血缘」行删除**；不显示距离、档位、乘数。
> 数据：出蛋时记录 `fatherUid` / `motherUid`（百变怪或无性别一侧记 `null`），用于区分父系 / 母系。

| 关系（候选相对栏内那只） | 称呼 |
|---|---|
| 候选是它的祖先，距离 1 / 2 / 3 / ≥4 | 父亲·母亲 / 祖父·祖母 / 曾祖父·曾祖母 / 先祖 |
| 候选是它的后代，距离 1 / 2 / 3 / ≥4 | 儿子·女儿 / 孙子·孙女 / 曾孙·曾孙女 / 后代 |
| 共享 2 位亲代（全同胞） | 哥哥·弟弟·姐姐·妹妹 |
| 共享 1 位亲代（半同胞） | 半兄·半弟·半姐·半妹 |
| 父之兄 / 父之弟 | 伯伯 / 叔叔 |
| 父之姐妹 | 姑姑 |
| 母之兄弟 | 舅舅 |
| 母之姐妹 | 阿姨 |
| 兄弟之子女 | 侄子 / 侄女 |
| 姐妹之子女 | 外甥 / 外甥女 |
| 父之兄弟的子女 | 堂兄·堂弟·堂姐·堂妹 |
| 父之姐妹、母之兄弟、母之姐妹的子女 | 表哥·表弟·表姐·表妹 |
| 双方最大距离 3 | 远房表亲 |
| 三代以外 / 无共同祖先 | **不标** |

**判定依据**：

- 直系：一方在另一方祖先表里，按深度取称呼；
- 全 / 半同胞：共享 2 / 1 位深度 1 的祖先；
- 父系 / 母系：看连接的那位亲代是 `fatherUid` 还是 `motherUid`；
- 堂 / 表：连接亲代**都是父亲**且互为兄弟 → 堂；其余同辈 → 表；
- 伯 / 叔：候选的 uid 小于父亲的 uid → 伯伯，否则叔叔；
- 侄 / 甥：连接亲代是兄弟 → 侄；是姐妹 → 甥；
- 表亲：双方距共同祖先都是 2；最大距离 3 → 远房表亲；
- **长幼**：同代按 `uid` 数值（小 = 年长），与展示编号无关。

**边界**：百变怪或无性别参与的那一侧 `fatherUid` / `motherUid` 为 `null`，该支称呼退化为粗版——「叔叔·阿姨」「侄子·侄女」「表亲」，不区分父系 / 母系。

**两处有意接受的近似**：

1. **长幼（含伯 / 叔）用 uid 先后**，不代表真实年龄；
2. **百变怪 / 无性别侧**无法判定父系母系，退化为粗称呼。

**理由**：称呼是玩家做「选谁配」这个决定所需的信息；档位与乘数不改变选择，因此不显示（与 §14 一致）。§16 的「界面只说近亲」随之收敛为「界面只说称呼」。

## 20. 蛋组错误的后代（畸形体）· 2026-11-24

> 状态：**✅ 视觉与规则数值均已定，已实施于 `231143d`**；实施对照见 §21。

### 20.1 起因

现行规则是：**异性 + 蛋组不匹配 → 争斗 → 死一只 + 永久锁对**。三个问题：

| 问题 | 说明 |
|---|---|
| 不合直觉 | 不同物种的异性不会互相残杀，它们只是配不上 |
| 试错代价是命 | 一次失败 = 死一只 + 锁一对 |
| 失败不产生知识 | 只记住"这对不行"，学不到任何可复用的东西 |

数据先摆出来：**144 个可繁育物种、15 个蛋组**，无序对 10296 组里只有 1571 组能配——**随机挑一对只有 15.3% 的成功率**。也就是说盲猜 6 次才对 1 次，而每次错的代价是一条命。

### 20.2 曾考虑的「宝可梦无限融合」——否决

规则层面完全可落地（头部 2/3 决定 HP/特攻/特防，身体 2/3 决定物攻/物防/速度；属性取头部第一 + 身体第二；特性各取其一），**卡在立绘数据上**：

| 事实 | 结论 |
|---|---|
| 第一世代融合全量 = 151² = **22,801 张**，约 500–600 MB | 静态站放不下 |
| `Aegide/custom-fusion-sprites` **已被 GitHub 以 ToS 关闭** | 公开素材源不可依赖 |
| 官方整包 **2.57–3 GB**，没有按需取单张的接口 | 无法懒加载 |
| InfiniDex 有结构化 API，但是**自托管 Docker**（FastAPI + PostgreSQL） | 不是公共服务 |
| 各类计算器站能看到图 | 无稳定单张 URL 规则，且是二创资产 |

> 顺带确认：**GitHub Pages 是可以请求外部资源的**（本项目 `data.mjs` 的 `remoteSprite()` 就在缺图时回退到 jsDelivr）。障碍不在技术，在于没有任何一个可依赖、授权干净的图源——主仓库已经因为 ToS 被关掉过一次。

**决定：放弃真融合图，用现有 151 张立绘程序化生成"畸形"。**

### 20.3 最终形态 ✅（涡流 + 轻度病变，单张立绘）

```css
filter: url(#warp-N) hue-rotate(140deg) saturate(.72) contrast(1.2);
```

```svg
<filter id="warp-N" x="-35%" y="-35%" width="170%" height="170%">
  <feTurbulence type="fractalNoise" baseFrequency="0.03 0.06"
                numOctaves="3" seed="N" result="n"/>
  <feDisplacementMap in="SourceGraphic" in2="n" scale="12"
                     xChannelSelector="R" yChannelSelector="G"/>
</filter>
```

```css
/* 尺寸一致：滤镜永远按 96px 算，再整体缩放 */
img.head{
  width: 96px; height: 96px;
  transform: scale(var(--k));      /* --k = 显示尺寸 / 96 */
  transform-origin: 0 0;
}
```

- **`N = hash(母方 dexId, 父方 dexId) % 997`**
- 同一对父母 → 永远同一副样子；**换父方 → 扭曲形态不同**
- 所以虽然外观只画母方，**父方仍然参与这张脸**

参数含义：`saturate(.72)` 是"颜色偏了但没坏死"（纯「腐」是 .18，原图是 1.0）；`scale=12` 是 12px 位移；`baseFrequency 0.03 0.06` 控制扭曲块的大小。

> **2026-11-24 修订（`Accepted, not implemented`，见 `docs/backlog.md` #1）**：立绘改为**按个体**生成——seed、位移量、频率、色相 / 饱和度 / 对比度全部从个体 `uid` 派生，同一只永远一样、不同个体互不相同。上方「同一对父母 → 永远同一副样子」**作废（Superseded）**，父母不再决定长相。

### 20.4 配套规则 ✅（2026-11-24 已定数值）

| 项 | 值 | 说明 |
|---|---|---|
| 触发 | 异性 + 不同蛋组 | 同蛋组仍是正常后代 |
| **死胎率** | **30%** | 期望 1.43 次尝试出 1 只 |
| **母方耐受** | **−44 / 次** | 正常配对是 40，只贵 10% |
| **父方耐受** | **−12 / 次** | 正常配对是 0，这是新增的 |
| **父方归零** | **死亡**（与母方同规则） | |
| 存活 | → 畸形体 | |
| 体质 | **0.5**（触底） | 耐受上限只有一半 |
| 繁育 | **不育** | 血统到此为止 |
| 图鉴 | **无条目**、不占图鉴 | |
| 研究 | **不推进任何物种研究** | 放进实验室也不给进度 |
| 样本 | **终末榨取 1 份** | 不能给 2 份，否则变成刷材料 |
| **交单** | **禁止** | 订单列表里不出现畸形体 |
| 出售 | 可卖，同物种普通个体的 **15–20%** | |

> 2026-11-24 决定：售价采用固定 **17%**（原 15–20% 区间取中值），实现为 `mutantSellFactor: 0.17`，出售时不加随机。

### 20.4.1 代价核算（以「正常一只后代 = 40 耐受」为基准）

| 维度 | 一只畸形体 | 倍数 |
|---|---|---|
| 母方耐受 | 63（44 × 1.43） | 1.6× |
| 父方耐受 | 17（12 × 1.43） | — |
| **合计耐受** | **80** | **2.0×** |
| 游戏内时间 | 3.6 天（≈43 秒真实） | 5.7× |
| 金币 | 0 | — |
| **产出价值** | **0.15** | **13.3×（按价值口径）** |

**父母能撑多久**：

| 母方等级 | 耐受上限 | 能出几只畸形体 |
|---|---|---|
| Lv.1 | 100 | 1.6 |
| Lv.30 | 158 | 2.5 |
| Lv.60 | 218 | 3.5 |

父方 12/次：Lv.1（125）可参与 10 次、Lv.60（273）可参与 22 次——**父方不是瓶颈，母方才是消耗品**。

**为什么耐受只贵 10%**：惩罚的主体是"后代是废物"（价值 0.15），耐受再加码就是双重惩罚。按价值口径，即使耐受压到最低，跨蛋组仍然是 13 倍亏损——它本来就该是"没有别的路时才走"。

### 20.4.2 两个已知风险（实施时要注意）

1. **父方死亡不可见**：耐受度只有在实验室里才显示，培育栏/围栏看不到。父方因跨蛋组配对耗尽而死，玩家事先没有任何提示，属于"暗坑"。**实施时先观察**；若玩家反馈突兀，再考虑在配对选择器给"扛不住这一胎"的个体标一个「虚弱」——那是决策相关信息，不违反 §14。
2. **30% 死胎率很便宜**（尝试成本只有 1.43 次），跨蛋组从"赌命"变成"可行"。这条成立的前提是**所有变现口都堵住**：禁止交单（已定）、卖价 15–20%、样本只有 1 份。任何一项放开，它都会变成稳定刷法。

### 20.5 蛋组知识的获得 ✅（2026-11-24）

**结论：蛋组名只由研究 100% 揭示；能不能配，看后代的形态。**

| 玩家想知道的 | 获得方式 |
|---|---|
| 这两个能不能配 | **看后代**：正常后代 = 蛋组匹配；畸形体 = 蛋组不匹配 |
| 这个物种属于哪些蛋组 | **研究进度 100%** 时揭示（之后永久可见） |
| 该拿谁去配 | 研究 100% 之后知道，或者试出来 |

配套改动：

- **取消"繁育成功揭示蛋组"**（原 `revealEggGroups` 的"成功一次揭示交集"）。蛋组不再从繁育里泄漏。
- 没研究完的物种仍是 `？？？`。
- 选择器里的"同蛋组绿框"只在**双方蛋组都已知**时出现——它不是主要判断依据，只是确认。
- 不再需要"失败也产出负信息"那套机制：**结果就是信息**。

### 20.6 死胎的信息问题 ✅（2026-11-24 选定 C）

跨蛋组的 30% 死胎，和正常配对因体质差产生的死胎（0–6%），**在结果上无法区分**——两者都只显示"这一胎没有成型"。

于是玩家看到一次死胎时，分不清是：

- 「配上了，但胎停」→ 说明蛋组是匹配的
- 「根本没配上，只是没到畸形体那一步」→ 说明蛋组不匹配

**选定 C：接受这个模糊。**

- 30% 与 0–6% 差着一个量级，玩家多试几次就能靠概率推断
- **不增加文案、不增加规则**——按 §14.7，不为"解释"多写一句
- 代价：新玩家第一次遇到死胎时无法判断。可以接受，因为他的下一步（再试一次）不受影响

曾考虑但否决的两个做法：

| | 做法 | 否决理由 |
|---|---|---|
| A | 两种死胎用不同文案 | 多一条只为解释而存在的文案，违反 §14.7 |
| B | 不匹配时不走"死胎"，栏位空转 | 最模糊，且不如 C 诚实（至少 C 给了概率） |

### 20.7 被否决的候选（记录理由，避免重走）

曾把"错误"拆成四种（腐 / 畸 / 错 / 裂）并考虑随机分配，后来试了更多做法，全部否决：

| 候选 | 做法 | 否决理由 |
|---|---|---|
| 裂（条带） | A 完整 + B 的细条带裁进 A 的轮廓 | 需要"用图片当 alpha 蒙版"，实现与调试成本高，且父母长得像时完全看不出 |
| 切片错位 | 同图切三条横移 | 太像"特效"，不像"长坏了" |
| 横撕 | SVG 逐行横向位移 | 与涡流重复，且组合后互相削弱 |
| 负片块 | 矩形区域反相 | 矩形读起来是"贴纸"，不是身体的一部分 |
| 肿块 | 圆形区域放大 | 只有一个位置，辨识度低 |
| 拖影 | 两层错位半透明 | 像"没对齐"，不像"活物" |
| 补丁（矩形） | 父方一块矩形贴到母方身上 | 同上，太规整 |
| 差值 / 蒙版反相 | 按父方轮廓做负片 | 想法对（形状来自父方），但颜色被父方污染，且依赖蒙版 |

**最终只用一种效果**：涡流本身就同时表达了"形状不对"和"它不该长这样"，比四种更好辨认；四种方案会让玩家花成本在"分辨类型"上，而分辨本身不改变任何决定（§14 的原则）。

### 20.8 技术教训（踩过的坑）

1. **SVG 位移滤镜的坐标是像素**：同一张图在不同尺寸下扭曲强度不同 → 固定 96px 渲染 + `transform: scale()`。
2. **不要用 `primitiveUnits="objectBoundingBox"`**：部分浏览器不把 `scale` 解释成百分比，`0.17` 变成 0.17px，效果直接消失。
3. **图片蒙版别通过 CSS 变量传**：`--m: url(...)` + `mask-image: var(--m)` 会拿不到图，整层被裁空 → 直接写内联 `style`。
4. **蒙版会建立合成上下文**：嵌套蒙版里的 `mix-blend-mode` 找不到可混合的背景，会退化成原图 → 改用 `filter: invert()`。
5. **`filter` 可以混写**：`url(#滤镜) hue-rotate(...) saturate(...)` 是合法的，先跑 SVG 位移再跑色彩函数，顺序反过来结果不同。
6. **诊断必须用高对比度配对**：烈雀 × 波波两只棕色小鸟，替换 20% 像素肉眼完全看不出——浪费了三轮调试。

### 20.9 围栏的「畸体」段 ✅（2026-11-24）

畸形体不进普通围栏列表，而是和「培育相关」「其它」**并列的第三段**。

| 项 | 规定 |
|---|---|
| 位置 | 与「培育相关」「其它」**同层级**，作为开关上的**第三段**（不是底部独立块） |
| 开关 | 从两段变三段：培育相关 / 其它 / **畸体** |
| 显示条件 | **只在存在畸形体时出现这一段**（按钮与内容都出现；没有畸体时开关仍是两段） |
| 普通列表 | 畸形体**不出现在**「其它」里，不重复展示 |
| 段头 | 「畸体 N 只」 |
| 段内可做 | 查看详情、出售、送进实验室 |
| 段内不可做 | 交单（§20.4）、放进培育栏（不育） |
| 围栏霸凌 | **不参与**——它们已经被单独归到这一段，不与同物种成群 |
| 遗体栏 | 不变，仍是底部独立块（它不是一个"分类"，是一堆待处理的东西） |

**为什么单独一段而不是塞进「其它」**：畸形体在规则上是"另一类东西"（无图鉴、不育、只能贱卖或做样本）。混在普通列表里会污染"我在养的那些"这条视觉主线；分开之后，玩家看到「其它」就是"还能用的"，看到「畸体」就是"该处理的"。

**为什么不做成底部独立块**：底部那块现在是「遗体」——它读起来是"垃圾待处理"。畸形体虽然也废，但**它是活的、能卖、能送实验室**，和遗体不是一回事。放进开关的同一层级，才表达"这是围栏的第三类东西"。
