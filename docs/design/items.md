## 10. 道具获取系统（讨论中，本轮主线）

> 因为能力值消费者暂缓（D-7），EV 道具目前只会改变详情页数字；
> 这批道具的阶段性意义是"成长资源"——给玩家可抢、可囤、可分配的东西。

### 10.1 已决定

| # | 决定 | 内容 |
|---|---|---|
| 10-1 | ✅ **独立 tab** | 与"部门需求"方向相反：部门向你要货，这里是你向组织要货 |
| 10-2 | ✅ **委托形态：混合** | 常规道具走"指定采购"（稳定、可规划）；稀有道具只能靠"目标掠夺"随机获得（有惊喜有风险） |
| 10-3 | ✅ **并入现有道具** | 进化石、通信电缆、经验糖果统一进这个入口；经营页的蛋贩子只保留卖蛋与换货 |

### 10.2 循环骨架

```
发布需求 → 火箭队出发 → 等若干天 → 带回战利品（或空手）→ 入库
```

### 10.3 目标设计（建议，未拍板）

可复用已有的 **300 条来源地点**文案（黑市中间人、走私船货舱、海关扣押仓库、火箭队运输车…）作为掠夺目标，按档位分组：

| 档位 | 示例 | 耗时 | 成本 | 成功率 | 产出 |
|---|---|---|---|---|---|
| 安全 | 近郊杂货铺 | 2 天 | 低 | 90% | 常规 EV 道具 |
| 普通 | 黑市仓库 | 3 天 | 中 | 75% | 常规 + 小概率稀有 |
| 冒险 | 海关扣押仓库 | 5 天 | 高 | 60% | 稀有概率较高 |
| 危险 | 火箭队运输车 | 7 天 | 免费 | 45% | 稀有概率最高，失败损失大 |

### 10.4 EV 道具粒度（建议，未拍板）

- 每颗 **+30 EV**（上限仍单项 252 / 总 510）
- 满一项约 9 颗；喂满一只约 17 颗
- 若每次委托带回 1–3 颗，喂满一只约 **6–10 次委托**

### 10.5 风险与反通胀（共识方向）

- 失败只损失时间与部分预付资金，**不损失个体**（个体死亡继续集中在实验室）
- 成功率与目标价值反相关，可随职级小幅提升
- 并发委托数随职级增长；目标列表定期刷新
- **不新增资源**（不做配额 / 行动力），用资金 + 时间 + 风险做取舍

### 10.7 定位补充：这是"道具容器"，不是 EV 专线

讨论确认：**EV 道具只是第一批道具**，后续会按游戏设定与正作道具的匹配度逐步增加。
因此这套系统要按"道具目录 + 获取渠道"来设计，而不是围绕 EV 写死。

建议的道具元数据（每条道具都要能填）：

| 字段 | 说明 |
|---|---|
| 分类 | 培育 / 研究 / 经营 / 特质 / 消耗品 |
| 获取渠道 | 可指定采购 / 只能掠夺 / 剧情或活动限定 |
| 稀有度 | 普通 / 稀有 / 极稀有（决定出现在哪一档目标里） |
| 价格 | 指定采购的固定价；掠夺线不标价，由目标成本体现 |
| 效果 | 作用对象（个体 / 蛋 / 栏位 / 全局）与数值 |
| 是否消耗 | 大部分消耗；少部分可重复使用 |

取舍原则（未拍板）：

- 本作**没有对战**，正作里偏战斗的道具（携带道具、树果、PP 提升等）价值低；
  优先挑"经营 / 培育 / 研究"类。
- 新增道具必须能挂到**现有玩法**上，否则只是又一个数字。
- 现有经营页的进化石与通信电缆、经验糖果 **已决定并入这个新入口**（见 10-3）；
  蛋贩子只保留卖蛋与换货，不再卖道具。

### 10.8 并入后的结构（建议，待拍板）

并入之后，"新 tab"里其实有两条不同的购买方式，需要先定节奏：

| 方式 | 确定性 | 耗时 | 占槽 | 定位 |
|---|---|---|---|---|
| **指定采购** | 必得 | 即时到货 | 不占 | 花钱买确定性，但**限量**（每类每日 1–2 件） |
| **目标掠夺** | 随机 | 2–7 天 | 占 | 花时间赌收益，可能出稀有 |

这样"混合"的取舍落在**钱 / 时间 / 确定性**三者的交换上，且保留了现有"点一下就到账"的商店手感；
稀缺性由"限量刷新"提供，而不是给每颗糖果都加等待时间。

如果改成"采购也要等 1–2 天"，体验会更像下军令，但日常消耗品（糖果）会变得繁琐。

### 10.9 新方向：个体作为"任务工具"（讨论中）

> 讨论中提出的方向：**派玩家培育的个体去执行掠夺任务，用个体的类型 / 特性 / 性格 / 能力等 meta 决定它能不能去、去得多好。**
> 目标：让"定向培育符合某种功能的宝可梦"成为经营策略，同时利用物种多样性，并贴合"火箭队把宝可梦当工具"的设定。

#### 为什么这个方向比"出售"有策略

- 出售是"把个体换成资源"，个体本身没有留存价值；任务派工是"个体持续产出"，且**派谁**会改变结果。
- 当任务需求由外部（目标场景）决定时，个体从"可互换的数量"变成"有岗位适配性的人员"。
- 繁育的目标从"多生"变成"生出能干某件事的个体"，闭环变成：
  **看任务需求 → 定向培育 → 派工 → 得道具 → 道具强化个体 → 接更难的活**

#### 设计原则（避免变成无聊玩法）

1. **资格与效率分离**：门槛决定"能不能去"（制造培育目标），效率决定"去得多好"（制造选优空间）。
2. **占用即代价**：任务期间个体不可用于繁育 / 出售 / 实验，形成机会成本。
3. **惩罚要轻**：失败主要是空手、掉耐受、轻伤；不轻易致死（死亡继续集中在实验室）。
4. **不新增系统**：任务只读已有 meta，不引入新资源。
5. **首版极简**：单任务、1–2 个需求标签、不做团队多槽、不做熟练度。

#### 资格维度（已决定）

- ❌ **不用性格**：25 种、池子大、目前没有变更手段，难以定向培育，容易把玩家卡住。
- ✅ **用特性 + 宝可梦分类（种类）**：这两类是与数值基本无关的 meta，适合作为机制门槛，也贴合"火箭队把宝可梦当工具"的设定。
- 注意：分类（genus，如"种子宝可梦"）此前因"没有用处"被整体删除（`fetch-data` 与 `dex.json` 都已剔除），现在要恢复。

#### 数据现状（2026-11-19 核对）

| meta | 分布 | 可观测 | 可定向 |
|---|---|---|---|
| 特性 | 151 物种：1 个的 6 种、2 个的 46 种、3 个的 99 种（含隐藏特性） | ❌ 不显示 | ❌ 随机、不遗传 |
| 分类 | 每物种 1 个（如"种子宝可梦""鸟类宝可梦"） | ❌ 已删除 | ✅ 选物种即定向 |

**结论**：分类天然可定向（选物种）；特性若保持"从 2–3 个里随机"，就会重演性格的问题。
因此在把特性当门槛之前，必须先定它的定向方式（见待定）。

#### 资格 vs 效率（两层）

- **资格（能不能去）**：物种级 meta（特性、分类）——制造"该繁育哪些物种"的目标。
- **效率（去得多好）**：个体级（等级、能力值、特质）——制造"派哪一只更强"的选择。
- 两层分开，既利用物种多样性，又不丢掉个体质量的意义。

#### 一个顺手的价值点：不孕不育

不孕/不育目前是纯负面。若任务系统存在，它们天然适合**高危任务**（没有繁殖价值，派出去不怕损失），
可以把"负面特质"变成"岗位适配"。同理，头目适合硬碰硬的任务，闪光适合需要稀有度的任务。

#### 待定

- [ ] **特性的定向方式**：A. 每物种固定主特性（`abilities[0]`，确定但特性门槛≈物种门槛）／B. 特性可遗传（多一层培育深度，但要先解决显示）／C. 特性胶囊道具（由掠夺产出）
- [ ] 分类字段的恢复方式（重新抓取 / 在 `data.mjs` 加覆盖表）
- [ ] 特性的可观测方式（直接显示 / 随研究进度披露）
- [ ] 任务失败的具体代价（掉多少耐受、是否受伤、是否可能逃跑/死亡）
- [ ] 是否允许多个个体同时执行一个任务（团队制会显著增加复杂度）
- [ ] 任务需求是明确显示还是模糊描述（模糊 → 更贴"研究"，但可能让玩家试错成本过高）

### 10.10 信息披露原则：所有个体信息都跟"研究进度"走

> 讨论确认的大方向：**个体的信息展示与披露，统一挂在物种研究进度上**，以强化"研究"这一行为的存在感。
> 特性此前因为没用被隐藏，现在既然要作为门槛，就恢复显示——但显示时机同样受研究进度控制。

#### 现状的不一致点

- 个体卡片：属性徽章、性格、等级一直显示
- 物种详情：属性、种族值按研究进度隐藏（未研究显示 `？？？`）
- 特性：完全不显示
- 分类：已删除
- 蛋组：另一套规则（繁育确认 / 研究 100% 补全）

同一份信息在"个体"和"物种"两个界面里的可见性不一致，玩家会困惑。

#### 建议：能力值按"解锁序列"逐项披露（草案）

这是**唯一需要测量**的信息，所以它继续按研究进度逐项公开：

```
六项能力值（按种族值从高到低）
```

- 研究进度条 = 测量进度，每约 16.7% 公开一项，100% 全部公开（与现有实现一致）
- 卡片上的 `？？？` 会随着研究推进逐项消失，玩家能感觉到"我越来越认识它了"
- 特性、分类、性格等**不上这条序列**，默认可见（见下）

#### 特性 / 分类：由「组织采样」解锁（已决定）

讨论最终确定：**特性与分类不做"默认可见"，改为行为解锁**。

| 项目 | 规则 |
|---|---|
| **解锁动作** | 对该物种的任意个体**首次完成「组织采样」且该个体存活** |
| **成功率** | 采样过程中个体死亡 **不算解锁**（已决定）；需要换一只再做 |
| **解锁范围** | **物种级**：一次解锁，该物种所有个体都可见分类与其自身特性 |
| **解锁内容** | 分类（种类）+ 特性（个体各自的特性随之可见） |
| **解锁前表现** | 卡片显示"特性未知 / 分类未知" |
| **派工拦截** | **只拦任务点名要求的标签**（已决定）：任务要求特性/分类、而该个体信息未知 → 不能派；任务没要求 → 不拦 |

理由与设定：你是研究员，取样之后才知道它是什么种类、有什么特性；
这也让「组织采样」这个基础实验有了研究之外的实际用途。

#### ⚠ 已知实现问题：有 6 个物种做不了「组织采样」

核对数据（2026-11-19）：专属实验条数分布 `{2:2, 3:143, 4:5, 5:1}`。
`experimentsFor()` 的补入规则是"不足 5 条才从基础三条里补"，具体补入顺序是 `对战 → 采样 → 体测`：

| 专属条数 | 补入内容 | 能否做组织采样 |
|---|---|---|
| 2 | 对战 + 采样 + 体测 | ✅ |
| 3 | 对战 + 采样 | ✅ |
| 4 | 只有对战 | ❌ |
| 5（#003 妙蛙花） | 不补 | ❌ |

也就是说：**5 个 4 条专属的物种 + 妙蛙花，永远无法通过采样解锁特性/分类**。

**已决定采用方案 A：让「组织采样」常驻**——不受补入规则影响，所有物种的实验室里都能看到它。
实施时的副作用：这 6 个物种的实验列表变成 5–6 条，
而"未做过的实验各压 2% 进度上限"的公式（`unperformed × 2%`）需要重新校准。

#### 由此产生的冲突：任务资格依赖"已知信息"

掠夺任务若按特性 / 分类筛人，玩家必须先"认识"这只个体。三种处理（未拍板）：

| 处理 | 效果 |
|---|---|
| **盲派** | 信息未知也能派，靠结果反推（贴"研究"，但试错成本高） |
| **禁止** | 信息未知的个体不能派 → 逼玩家先研究该物种（门槛清晰，但可能卡住） |
| **模糊提示** | 显示"看着像是能派上用场的"之类定性判断，不保证 |

#### 待定

- [x] 任务资格在信息未知时的处理：**拦截**（已决定，见上表）
- [x] 采样过程中个体死亡：**不算解锁**
- [x] 拦截范围：**只拦任务点名要求的标签**
- [ ] ~~**采样可用性**：方案 A（常驻）／方案 B（独立动作）~~ → **已定：方案 A**，注意重算 `unperformed × 2%`
- [ ] 任务界面如何提示"需要先做组织采样"
- [ ] 个体卡片与物种详情的可见性是否要统一到同一套规则

### 10.11 美术：性别立绘（讨论中）

**现状**：`data/sprites/` 里每个物种只有一张 `{id}.png`（默认图），`sprite(id)` 不带性别；
性别只靠卡片上的 `♂ / ♀ / —` 符号区分。抓取脚本也只抓默认图，没有 female 目录。

**事实**：PokeAPI 的 `sprites/pokemon/female/{id}.png` 提供雌性立绘，但**第一世代里有性别差异的物种很少**
（典型如皮卡丘的尾巴缺口），其余多为第四世代之后才追加的差异。

**讨论结论（未拍板）**：

- 卡片上的立绘只有约 64px，细微差异（尾巴缺口之类）很可能看不清；性别符号仍然是更可靠的识别方式。
- 若要做，正确做法是**只补确有差异的少数物种**，并让 `sprite(id, gender)` 在缺失时回退默认图，
  不要为了统一给 151 个物种都放大一套 female 图。
- 视觉差异属于"一眼看到"的观察，**不应受研究进度限制**（与研究解锁的是"知识"，不是"外观"）。

- [ ] 是否加入性别立绘；若加，先确认第一世代实际有差异的物种清单
- [ ] 是否需要"熟练度/专精"（建议首版不做）

### 10.12 任务形态与文案（2026-11-20 讨论）

#### 卡面文案模板（已定）

> **【职级】【随机人名】要去【干什么坏事】需要【某种条件】的宝可梦**

一句话解决三件事：谁在指使人（有了主语）、你的宝可梦为什么会在场（被借走）、难度靠什么感知（职级，而不是百分比）。

#### 已定

| # | 决定 | 内容 |
|---|---|---|
| 10-4 | ✅ **文案模板** | 职级 + 随机人名 + 坏事 + 条件，一句话成卡，不另设字段 |
| 10-5 | ✅ **职级 = 难度信号** | 复用 `RANKS` 六级；职称越高，接的活越险。界面**不显示成功率**（入 README 隐性设定表） |
| 10-6 | ✅ **条件用"岗位"，不用"特性"** | 不维护 114 行「特性 ↔ 白话」一对一表；维护 12–16 行**岗位表**：一行 = 一句白话 + 一个判定，判定可 OR 多个 meta。**岗位名不显示给玩家** |
| 10-7 | ✅ **派遣只列合格个体** | 岗位判定不通过的个体不进派遣列表；信息未解锁（未完成「组织采样」）显示"还没摸清它的性子"并锁定 |
| 10-8 | ✅ **单人派遣** | 每单 1 只个体；首版不做组队。资格判定一次、失败只影响这一只。组队留待后续版本（加第二个派遣位即可，不用改结构） |

#### 为什么不做「特性 ↔ 白话」一对一表（核对过 `data/dex.json`）

| 事实 | 数字 |
|---|---|
| 特性总数 | 114 |
| 平均每个特性被几个物种携带 | 3.46 |
| 中位数 | 3 |
| 只被 1 个物种携带 | 24 个 |
| 被 ≥5 个物种携带 | 30 个（悠游自如 13、叶绿素 12、逃跑 11、精神力 11） |

再叠加"**这一只个体**正好带这个特性"（3 特性物种约 1/3），随机点名一个特性就是运气墙，不是培育目标。
岗位表用 OR 把判定放宽后，一个岗位覆盖 9–49 个物种，任务总有解。

| 跑腿 | 跑得快、不叫唤 | 速度 ≥ 90 | 42 |
| 苦力 | 能扛能跑、不怕磕碰 | 特性·结实 或 体重 ≥ 600 | 38 |
| 断电 | 能让一片街区停电 | 属性·电 | 9 |

### 10.13 v1 范围调整：先做金币商店（2026-11-20）

| # | 决定 | 内容 |
|---|---|---|
| 10-9 | ✅ **v1 只做金币商店** | 道具全部并入一个商店、用资金购买；**不做掠夺任务** |
| 10-10 | 🕒 **任务那套整体暂缓** | §10.3 / §10.9 / §10.12 的据点、岗位、文案模板、效率层全部保留为**以后的设计底稿**：不实施、不删 |

理由：

- 道具系统（容器 + 获取渠道）本身可以先立起来，不依赖任务。
- 但任务的价值（效率层、产出消费端）依赖还没定的系统，现在做等于给空循环加装饰。
- 先把商店做出来，等个体价值/消费端有结论，再把商店改造成"物资 / 掠夺"的设定形态。

连带结论：

- **"个体质量没有出口"这个原始问题暂时不解**——它本来要靠任务的效率层，现在整体推后。
- §10.12 的岗位表与文案模板不作废：改商店时直接复用（据点 → 货架、带队人 → 供货人，设定替换即可）。

价格基准（2800/颗）：

| 投入 | 颗数 | 花费 |
|---|---|---|
| 满一项（252） | 1 | 2800 金 |
| 满两项 | 2 | 5600 金 |

参照：中期一单部门需求约 460–860 金（Lv.20–40、普通部门），满两项约等于 6–12 单；与设施升级（2000–24000）同一量级。

**简化说明**：原方案是"一颗 +30 EV、单项 252 / 总 510"，满一项要 9 颗、满一只 17 颗。改成"一颗拉满一项、每只两项"之后：

- 点击从 9 次/项降到 1 次，商店从"消耗品"变成"一次性投资"。
- 中间态（30/60/…/252）消失。这个游戏的渐进轴由**等级**承担，EV 变成"押哪两项"的一次性决策。
- 代价：喂到一半的经营手感没了；但 9 次点击本身也没什么乐趣。
- 附带好处：一颗 = 一项拉满，以后做成掠夺产出时，它就是天然的头奖。
