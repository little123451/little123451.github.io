## 0. 一句话

繁育是「产线 + 样本库」：母体是耗材，蛋是货也是实验材料。

本次**不改核心循环**（放两只 → 2.5 天 → 出蛋），只补**近亲 / 体质**这一层长期约束，外加五处表达修补。

## 2. 逐条规格

### 2-1 开局 3 只

现状：`createMon(state, 16, 5, {gender:'m'})` + `createMon(state, 21, 5, {gender:'f'})`。

改为三只：

| 位置 | 物种 | 性别 | 等级 | 要求 |
|---|---|---|---|---|
| 1 | 波波（16） | ♂ | 5 | 父本，用来教「子代随母方」 |
| 2 | 烈雀（21） | ♀ | 5 | 母体 A |
| 3 | 烈雀（21） | ♀ | 5 | 母体 B，**必须与母体 A 无亲缘**（`ancestors: []`） |

- 两只雌性**必须同物种**，否则断线风险不会下降（异种双雌 = 每条线各 3 胎，风险不变）。
- 设定依据：基地配发的第一批样本是三只。

### 2-2 力竭结算：先产蛋，再死

现状：`if (bearer.tolerance - 32 <= 0) → 死亡，不产蛋`。

改为：

```
蛋位满 → 等待（不变）
↓
bearer.tolerance -= CONFIG.breedToleranceCost   // 40
revealEggGroups + createEgg
↓
if (bearer.tolerance <= 0) → 力竭死（留遗体）
```

- 效果：每只母体多产一胎。
- 与 2-11 的消耗上调（32 → 40）一起，产胎数基线仍为 **4**（详见 §3）。

### 2-3 祖先表去掉上限

`lineageOf()` 里删掉 `.slice(0, 8)`。

- 现状的 8 条会把母本挤出祖先表，**连亲子都判不出来**。
- 数组随代数线性增长（每代 +1~2），存档体积可接受。

### 2-4 体质系数 `vigor`

新字段：`mon.vigor` / `egg.vigor`，默认 `1`。

**计算（在 `createEgg` 里）**：

```js
const kin = isKin(a, b);
const vigor = kin
  ? Math.max(CONFIG.vigorFloor, Math.min(a.vigor, b.vigor) * CONFIG.kinVigorFactor)
  : Math.min(1, (a.vigor + b.vigor) / 2 + CONFIG.hybridVigorBonus);
```

| 常量 | 值 |
|---|---|
| `CONFIG.kinVigorFactor` | 0.85 |
| `CONFIG.vigorFloor` | 0.5 |
| `CONFIG.hybridVigorBonus` | 0.2 |

**作用点**：乘在耐受上限上。

```js
export function maxTolerance(mon) {
  const base = toleranceCap(mon?.level ?? 1, mon?.gender);
  return Math.max(1, Math.round(base * (mon?.vigor ?? 1)));
}
```

- `toleranceCap(level, gender)` **签名不变**，只在 `maxTolerance` 里乘 `vigor`。
- 不新增任何界面数值——它体现为耐受灰度变短。

### 2-5 近亲判定

```js
export function isKin(a, b) {
  if (!a || !b) return false;
  const A = new Set(a.ancestors || []);
  const B = new Set(b.ancestors || []);
  if (A.has(b.uid) || B.has(a.uid)) return true; // 亲子
  for (const u of B) if (A.has(u)) return true;  // 共同祖先
  return false;
}
```

- 不区分亲缘远近，只有一个「近亲」。
- `compatibility(a, b)` 的返回体加 `kin: true` 标记（**不改变 `ok`**，近亲仍然可配）。

### 2-6 死胎

在 `resolvePen` 的成功分支里，产蛋**之前**判定：

```js
function stillbirthChance(vigor) {
  if (vigor >= 0.85) return 0;
  if (vigor >= 0.72) return 0.02;
  if (vigor >= 0.61) return 0.04;
  return 0.06;
}
```

命中死胎时：

- **照常扣 32 耐受**
- 不产蛋，`pen.breed = 0`
- 事件：`type: 'warn'`，文案 **「这一胎没有成型。母体照样耗掉了这一次。」**
- 记入全局日志（`pushLog`），**不进实验日志**（那是实验室的）

| 个体详情 | **「近亲后代 · 第 N 代」** | `mon.inbred === true`（出生时写入，`gen` 已有） |

- 未研究：维持现状（不显示 IV）

### 2-9 繁育栏卡片减负

|---|---|
| 属性徽章 `.types` | **删** |
| 经验条 `.bar.exp`（含 `patchSlot` 里的宽度更新） | **删** |

### 2-10 孵化反馈分级

`hatch()` 与 `handleEvents` 配合：

| 情况 | 反馈 |
|---|---|
| 普通孵化 | **只进日志**，不弹 toast |
| `vigor < 0.85`（虚弱） | 强调：toast + 日志 |
| 不孕 / 不育 | 强调 |
| 闪光 | 强调 |
| 首次孵出该物种 | 强调（需要新字段 `state.everHatched = {}`） |

### 2-11 产蛋耐受消耗：32 → 40

`rules.mjs`：

```js
breedToleranceCost: 40,   // 原值 32
```

**为什么上调**：2-2 的「先产后死」让每只母体多产一胎，把产量推高到 5；把消耗提到 40，产量回到 **4 胎**，母体仍然是耗材。

**副作用（已知并接受）**：消耗越高，升级回补的耐受占了总预算的比例越大，**近亲造成的产量差异会被压缩**（32 时是 5→2，40 时是 4→2，50 时会变成 3→2）。近亲的代价因此更多体现在死胎率与耐受上限上，而不是单纯少产几胎。

### 2-12 选择器：同蛋组个体给绿色边框

在培育栏空位点「放入宝可梦」时（`pickerModalHtml`），对候选做一个**已知蛋组**的比对：

| 项 | 规则 |
|---|---|
| 条件 | 候选与该栏位另一只的**已识别蛋组**有交集（`knownEggGroups` 交集非空） |
| 表现 | 候选卡片加一个**微弱的绿色边框**（`box-shadow` 内描边，不改布局） |
| 文案 | **不加任何文字**（§14.7） |
| 数据来源 | 只用 `state.eggKnown`，**不揭示未知蛋组** |

**为什么只用“已识别”的**：这是记忆辅助，不是剧透。玩家已经通过繁育或研究知道了这两个物种共享某个蛋组，界面帮他把这件事记住——但如果还没识别，就没有提示，仍然要靠试。

**两个边界**：

- 栏位另一侧是空的 → **不提示**（没有比对对象）
- 一方是**百变怪** → **永远不亮**。它的已知蛋组是 `ditto`，与任何物种都不交集；不做特判，也不提前暴露“百变怪万能”

## 6. 手动验收（浏览器）

1. 新档开局：3 只，一雄两雌，两只雌性同物种
2. 放一雄一雌：2.5 天后产蛋，母体耐受 −32；连产到第 5 胎后力竭死，遗体占位
3. 用女儿回交父本：选择器显示「近亲」；孵出的个体详情显示「近亲后代 · 第 2 代」，耐受灰度明显更短
4. 连续自交 3 代：产胎数从 5 降到 3，偶发「这一胎没有成型」
5. 用市场蛋引入外血：后代体质回满，产胎数回升
6. 把某物种研究到 100%：详情页出现六项 IV；繁育栏卡片仍然干净
